# Karpathy Behavioral Guidelines (Принципы Карпатого)

Поведенческие принципы Андрея Карпатого для устранения типичных ошибок LLM при разработке:

## 1. Думай перед написанием кода (Think Before Coding)
- **Не додумывай молча**: явно формулируй допущения; при неопределенности задавай вопросы.
- **Освещай компромиссы**: если есть несколько трактовок, озвучивай их, а не выбирай вслепую.
- **Останавливайся при неясности**: если требование двусмысленно, сначала уточни.

## 2. Простота превыше всего (Simplicity First)
- **Минимальный код, решающий задачу**: никакого спекулятивного функционала «на будущее».
- **Без лишних абстракций**: не создавать обобщения и фабрики для одноразового кода.
- **Без избыточной конфигурабельности**: не добавлять опции, о которых не просили.
- **Лаконичность**: если 200 строк можно записать в 50 — перепиши в 50.

## 3. Хирургические точечные изменения (Surgical Changes)
- **Трогай только то, что необходимо**: не «улучшай» соседний несвязанный код, комментарии или форматирование.
- **Не чини то, что работает**: сохраняй существующий стиль проекта.
- **Убирай за собой**: удаляй импорты, переменные и методы, которые стали неиспользуемыми из-за твоих изменений. Не удаляй ранее существовавший чужой мертвый код без явной просьбы.
- **Тест каждой строчки**: любая измененная строчка должна напрямую относиться к запросу пользователя.

## 4. Целевое выполнение с проверкой (Goal-Driven Execution)
- **Определяй проверяемые критерии успеха**: формулируй проверяемые цели (тесты, компиляция, HTTP-ответы).
- **План с верификацией**:
  ```
  1. [Шаг] → проверка: [как верифицировать]
  2. [Шаг] → проверка: [как верифицировать]
  ```
- **Цикл до подтверждения**: итерируй автономно, пока все критерии успеха не подтверждены фактами.
