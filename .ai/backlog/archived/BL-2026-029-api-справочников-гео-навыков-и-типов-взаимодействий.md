## Исходная мысль руководителя

> Получения по API значений справочников (гео, навыки, типы взаимодействий. ...)

## Проблема и бизнес-сценарий

Внешнему приложению нужны актуальные идентификаторы и отображаемые значения справочников, чтобы создавать вакансии, кандидатов, CV и взаимодействия через API без передачи неподтверждённых строк и без расхождения с HRM.

## Что уже доступно

- [rest-queries.xml](/Users/alekseyananyev/StudioProjects/hunttech_recruiting/modules/web/src/com/company/hunttech/rest-queries.xml) уже содержит read-запросы `cityAll`, `positionAll`, `projectAll` и `gradeAll` с `_minimal` view.
- В модели проекта есть `City`, `Region`, `Country`, `SkillTree`, `Iteraction`, `Position`, `Grade`, `Project`, `Company` и другие ссылки, используемые при создании вакансий и кандидатов.
- Текущие запросы не образуют единого versioned reference-контракта: нет согласованных форматов, фильтров, pagination/updated-since, локализации и правил доступа.

## Предварительный состав API

Read-only versioned endpoints или единый namespace:

- география: страны, регионы, города;
- навыки: дерево/узлы навыков с ID, названием, родителем и активностью;
- типы взаимодействий: код, название, признаки сценария и активности;
- должности и грейды;
- проекты и компании, если они нужны для выбора в API вакансий/кандидатов;
- при необходимости — владельцы/рекрутеры в безопасном ограниченном представлении.

Каждый ответ должен иметь стабильные IDs, локализованные подписи, признак активности, `updatedAt`/версию справочника и pagination/filtering. Системные/секретные поля и удалённые записи не выдавать без отдельного разрешения.

## План и критерии

- составить каталог справочников и владельцев данных;
- определить единый формат ответа, локали, сортировку, поиск, пагинацию и инкрементальную синхронизацию;
- ограничить доступ по scope и выдавать только необходимые поля;
- добавить кэширование/ETag или version token для больших справочников навыков и географии;
- проверить, что ID из API принимаются write-endpoint без неоднозначного поиска по названию;
- покрыть тестами фильтрацию, локализацию, inactive/deleted значения, pagination, права и стабильность идентификаторов;
- документировать версионирование и обратную совместимость.
