## Исходная мысль руководителя

> на будущее: API интеграция с Хабр-карьерой

Предыдущая формулировка, по которой BL-2026-017 уже упоминалась в карточках API-задач: «интеграция с ХабрКарьерой по API».

## Проблема и ожидаемый результат

Нужна интеграция HRM HuntTech с Хабр Карьерой через API. Точные сценарии обмена не определены. После анализа API и бизнес-процесса ожидается согласованный контракт, позволяющий выполнять утверждённые операции между системами с контролем прав и обработкой ошибок.

## Расследование текущей реализации и документов

### Подтверждённые факты по репозиторию

- В `modules/web/src/com/company/hunttech/web/screens/openposition/smart-open-position-upload-screen.xml` форма «Умная загрузка вакансий» сообщает о загрузке по ссылке и указывает публичные URL вакансий Хабр Карьеры (`career.habr.com/vacancies/...`).
- В `modules/web/src/com/company/hunttech/web/screens/jobcandidate/smart-cv-upload-screen.xml` форма «Умная загрузка резюме» принимает ссылки на профиль/резюме Хабр Карьеры.
- Это подтверждает существование сценариев обработки публичных страниц по ссылке, но не подтверждает прямой официальный API-коннектор, OAuth-доступ, публикацию вакансий в Хабр Карьере или обратную синхронизацию.
- Карточки BL-2026-025 и BL-2026-027 ссылались на BL-2026-017, однако отдельный файл BL-2026-017 в текущем `.ai/backlog/` отсутствовал. Эта карточка восстановлена с ранее использовавшимся ID, чтобы сохранить ссылки и историю.
- BL-2026-036 описывает безопасный API-контур внешних приложений, входящих в HRM; интеграция с площадкой может использовать часть его security/аудит-принципов, но является отдельным vendor connector и не добавляется в заявленные шесть work packages подпроекта.

### Действия при выполнении

1. Изучить актуальную официальную документацию/API Хабр Карьеры, доступные методы, типы токенов, ограничения, лимиты и условия использования; зафиксировать ссылку и дату проверки.
2. Уточнить бизнес-сценарий: импорт вакансий, публикация/обновление вакансий, получение откликов/кандидатов, статусы, поиск резюме либо конкретная комбинация этих операций.
3. Сопоставить внешний контракт с HRM-сущностями и существующими сценариями «Умная загрузка вакансий/резюме»; определить, что переиспользуется, а где нужен отдельный API-клиент.
4. Подготовить карту данных, соответствие справочников, правила дублей и идемпотентности, расписание/направление синхронизации и требования к журналу ошибок.
5. Спроектировать хранение credentials, scopes, права CUBA, ротацию и аудит без попадания секретов/персональных данных в логи.
6. Оценить ограничения API поставщика и определить безопасный rollout, тестовый контур и процедуру отключения интеграции.
7. Только после согласования сценариев и контракта декомпозировать и реализовать интеграцию отдельными PR с тестами и документацией.

## Предварительные критерии готовности

- Подтверждены доступные и разрешённые API-возможности Хабр Карьеры; в документации задачи указаны источники и дата их проверки.
- Владелец утвердил точный набор направлений и операций интеграции.
- Описаны контракт данных и переходы состояний, соответствия справочников, правила дублей/идемпотентности и retry.
- Доступ ограничен выделенной интеграционной учётной записью и минимальными правами; секреты защищены и ротируемы.
- Сбои API диагностируются по correlation ID без утечки секретов и лишних ПДн.
- Тесты покрывают успех, истёкшие/недействительные credentials, лимиты/временную недоступность, повтор запроса, конфликт данных и ошибку валидации.
- Текущая загрузка публичных страниц по URL продолжает работать, если отдельным решением не утверждена её замена.

## Открытые вопросы и допущения

- Вопросы: какие именно данные и в каком направлении передавать; нужна ли публикация вакансий, импорт откликов и/или синхронизация статусов; какой пользователь/организация Хабр Карьеры будут подключены; какие объёмы и частота обмена ожидаются.
- Вопросы: предоставляет ли площадка подходящий API и доступ HuntTech к нужным endpoint-ам; есть ли тестовый контур и ограничения коммерческого тарифа/договора.
- Допущение: «API-интеграция» подразумевает машинный обмен через поддерживаемый API поставщика и не сводится к текущей загрузке открытой страницы вакансии/профиля по URL.
