## Исходная мысль руководителя

> API отдельно для создания CnaidateCV и IteractionList.

## Проблема и бизнес-сценарий

Помимо пакетного API кандидата нужен раздельный приём новых версий резюме и новых взаимодействий: резюме может поступать позже карточки, а взаимодействие — после действий рекрутера или внешнего процесса.

## Подтверждённый контекст модели

- `CandidateCV` требует `candidate` и `datePost`; поддерживает текст, письмо, ссылки, привязку к вакансии/должности, владельца и файлы.
- `IteractionList` требует `candidate`, `vacancy` и `recrutier`; содержит дату, тип взаимодействия, способ коммуникации, комментарий, рейтинг и календарные поля.
- Текущий [rest-queries.xml](/Users/alekseyananyev/StudioProjects/hunttech_recruiting/modules/web/src/com/company/hunttech/rest-queries.xml) содержит read-запросы и не описывает write API этих сущностей.
- Внешний generic CRUD не подходит: нельзя позволять клиенту произвольно менять владельца, рекрутера, календарные поля и системные audit-поля.

## Предварительный контракт

Раздельные versioned endpoints:

- `POST /api/integrations/v1/candidate-cvs` — создать CV для существующего кандидата;
- `POST /api/integrations/v1/interaction-lists` — создать взаимодействие для существующего кандидата, вакансии и рекрутера.

Оба endpoint должны поддерживать внешний ID/idempotency key, узкие DTO, проверку FK и стабильные ответы с внутренним ID, внешним ID и correlation ID. Для CV отдельно описать текст/ссылки/файл и лимиты; для взаимодействия — timezone, тип, дату, рекрутера, вакансию и допустимые календарные параметры.

## План и критерии

- определить create-only или upsert для каждого endpoint;
- обеспечить идемпотентность и защиту от повторных CV/взаимодействий;
- валидировать принадлежность кандидата, существование вакансии и право назначить рекрутера;
- не менять существующие UI-сценарии и не раскрывать секреты/лишние персональные данные;
- покрыть тестами успешный create, дубль, неизвестные FK, запрещённого рекрутера, неверную дату/тип, файл CV и безопасный rollback;
- опубликовать документацию API и формат ошибок.
