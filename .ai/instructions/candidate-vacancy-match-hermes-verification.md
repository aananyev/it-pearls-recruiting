# Hermes: проверка подбора кандидата по открытым вакансиям

## Контекст

- Проект: HRM HuntTech
- Репозиторий: `aananyev/it-pearls-recruiting`
- Ветка: `agent/candidate-vacancy-match-layout-report`
- Base: `master`
- PR и полный проверяемый HEAD SHA: указаны в описании PR. Перед проверкой сравнить SHA PR с SHA ветки; при несовпадении остановиться со статусом `HEAD_MISMATCH`.
- Режим: проверка без изменения кода и документации.

## Проверки

1. Убедиться, что PR открыт из `agent/candidate-vacancy-match-layout-report` прямо в `master`, checkout соответствует полному HEAD SHA из описания PR, конфликтов нет.
2. Выполнить целевые тесты:

   ```bash
   ./gradlew :app-core:test \
     --tests '*CandidateSkillEnrichmentServiceTest*' \
     --tests '*CandidateVacancyMatch*' \
     --tests '*ScreenViewIntegrityTest*' \
     --no-daemon --stacktrace
   ```

   Для `ScreenViewIntegrityTest` подтвердить `8/8 PASS`.

3. Собрать SCSS:

   ```bash
   ./gradlew :app-web:buildScssThemes --no-daemon --stacktrace
   ```

4. Выполнить полную сборку:

   ```bash
   ./gradlew clean assemble --no-daemon --stacktrace
   ```

   Ожидается `BUILD SUCCESSFUL`.

5. Выполнить local deploy и smoke по штатному runbook: `/hrm/` отвечает HTTP 200, в Tomcat logs нет ошибок, проверить открытие диалога, три этапа прогресса, результаты/детали и существующие действия рекрутера.

## Функциональные сценарии

- При открытии диалога сравнить дату последнего CV с максимальной датой `createTs/updateTs` навыков: свежие навыки не запускают извлечение; если навыков нет или CV новее, вызывается стандартная AI-функция извлечения и сохранённые `CandidateSkill` доступны анализу.
- При поиске включаются только вакансии с `openClose=false` или `openClose=null`; `openClose=true` не попадает ни в один AI-пакет и не появляется в результатах.
- AI сопоставляет структурированные навыки кандидата, текст резюме, навыки и требования вакансии; проверяются score/подсчёт компонентов, совпавшие навыки, критические пробелы и обоснование результата.
- Во время работы отображаются этап и статус, фактический прогресс по завершённым пакетам, число обработанных вакансий, прошедшее время и ETA после появления измеряемой скорости.
- Проверить пустой список открытых вакансий, отсутствие резюме, ошибку обновления навыков и частичный отказ AI: состояние экрана остаётся понятным, сохранённые навыки не очищаются.
- Проверить диалог в размерах 1100×780, 900×650 и 768×600, включая масштаб браузера 125%: верхние блоки и действия переносятся без наложения; при ширине до 1000 px таблица и детали идут вертикально, каждая панель прокручивается независимо.
- Сопоставить диагностику `docs/ai/CandidateVacancyMatch_AI_Fallback_Incident_Report.md` с текущим `AiExecutionServiceBean`: расшифровка credential в text/streaming/image путях находится до per-candidate `try/catch`. Это диагностический пункт; изменять AI-конфигурацию или production запрещено.

## Ограничения

- Не менять функциональный код или `docs/`, не создавать коммиты и не отправлять push.
- Не выполнять merge, production deploy, restart, миграции или изменения production-данных.
- При успехе выставить `STATUS: READY_TO_MERGE` только если все требуемые проверки прошли на проверяемом SHA, `base=master`, конфликты отсутствуют, docs синхронны, P1=0 и P2=0. Merge не выполнять.
- При ошибке вернуть `STATUS: FAILED_VERIFICATION`, шаг, причину и log/stack trace; код не менять.
