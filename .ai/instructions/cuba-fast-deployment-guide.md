# Быстрый деплой (Fast Deployment) в CUBA Platform 7.3: Руководство для агентов

> **Статус**: Действующий стандарт  
> **Целевая аудитория**: Hermes-1, Hermes-2, Antigravity  
> **Основание**: Документация CUBA Platform (Deployment in Development / Fast Deployment), протокол трех агентов.

---

## 1. Проблема традиционного полного деплоя (Full Clean Deploy)

До внедрения быстрого деплоя каждый запуск через `scripts/start-app.sh` выполнял:
1. Остановку процесса Tomcat;
2. Удаление каталогов exploded-приложений (`rm -rf webapps/hrm webapps/hrm-core work/Catalina/...`);
3. Полный `clean` проекта Gradle;
4. Полную перекомпиляцию всех модулей с нуля;
5. Компиляцию всех 7 тем SCSS (`buildScssThemes`) — ~1 минута;
6. Компиляцию GWT WidgetSet (`buildWidgetSet`) — ~1.5 минуты;
7. Холодный запуск Tomcat и прогрев контекста CUBA — ~1–2 минуты.

**Итоговый цикл полного деплоя**: **4 минуты 26 секунд** на любое, даже точечное исправление одной строки в XML или Java.

---

## 2. Механизм быстрого деплоя CUBA Platform (Fast Deployment)

CUBA Platform изначально спроектирована для быстрой разработки и поддерживает многоуровневую модель инкрементального развертывания без необходимости перезапуска сервера:

```
┌───────────────────────────┬───────────────────────────────┬──────────────┬──────────────────────────────────┐
│ Что изменилось            │ Целевая Gradle-задача         │ Время цикла  │ Нужен ли перезапуск Tomcat?      │
├───────────────────────────┼───────────────────────────────┼──────────────┼──────────────────────────────────┤
│ 1. XML-экраны и Messages  │ :app-web:deployConf           │ 2–4 секунды  │ НЕТ (горячее чтение из conf)     │
│ 2. Java-контроллеры (web) │ :app-web:deploy -x test       │ 10–20 секунд │ НЕТ / легкий reload контекста    │
│ 3. Стили (SCSS)           │ :app-web:deployThemes         │ 20–30 секунд │ НЕТ (Ctrl+Shift+R в браузере)    │
│ 4. Сервисы (core)         │ :app-core:deploy -x test      │ 10–20 секунд │ Перезапуск контекста hrm-core    │
│ 5. GWT виджеты (toolkit)  │ :app-web-toolkit:deploy       │ 1.5–2 минуты │ ДА (перезапуск Tomcat)           │
│ 6. Миграции БД (Liquibase)│ updateDb + restart            │ 1–2 минуты   │ ДА (только Hermes-1 на master)   │
└───────────────────────────┴───────────────────────────────┴──────────────┴──────────────────────────────────┘
```

## 3. Матрица применимости для агентов разработки

### Для агентов-разработчиков (Antigravity и Hermes-2):
- **При верстке и настройке экранов (XML, локализация `messages*.properties`)**:
  Запускать только горячий деплой конфигурации:
  ```bash
  bash scripts/fast-deploy.sh --conf
  ```
  *(время: 3 секунды, Tomcat не перезапускается, в браузере достаточно закрыть и снова открыть экран)*.

- **При правках Java-кода в веб-модуле (`screens/**/*.java`)**:
  Запускать инкрементальный веб-деплой:
  ```bash
  bash scripts/fast-deploy.sh --web
  ```
  *(время: 15–20 секунд без перекомпиляции SCSS и WidgetSet)*.

- **При изменении SCSS-стилей**:
  Запускать точечный деплой тем:
  ```bash
  bash scripts/fast-deploy.sh --themes
  ```
  *(время: ~25 секунд)*.

### Для агента CI/CD (Hermes-1):
- Полный `scripts/start-app.sh` запускается **только**:
  1. При слиянии PR в `master` с новыми миграциями БД (`updateDb`);
  2. При изменениях в `build.gradle` (новые зависимости, аддоны);
  3. При изменении виджетов `web-toolkit` (`AppWidgetSet`);
  4. При контрольном релизном деплое master.

## 4. Правила изоляции и безопасности при быстром деплое

1. **Единый Mutex (`.local-deploy.lock`)**:
   Все быстрые деплои обязаны использовать глобальный lock-файл через `shlock`, чтобы исключить параллельный запуск с другим агентом или сборкой Hermes-1.
2. **Запрет `clean` во время локальной разработки**:
   Никогда не запускать `./gradlew clean` при точечной разработке экранов. Флаг `clean` сбрасывает кэш виджетов и тем, возвращая 4.5-минутный простой.
3. **Защита БД**:
   Быстрый деплой не применяет миграции к БД. Любые миграции выполняет только Hermes-1 на master через `scripts/start-app.sh`.
4. **Очистка кэша браузера**:
   После обновления стилей SCSS или XML-компонентов всегда выполнять жесткую перезагрузку в браузере (`Ctrl+Shift+R` / `Cmd+Shift+R`).
