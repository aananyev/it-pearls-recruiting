# Брифинг субагента: «Промпт-инженер» (AI Prompt Engineer)

РОЛЬ: **Промпт-инженер** (AI Prompt Engineer)  
СИСТЕМА: **HRM HuntTech** (CUBA Platform 7.3, PostgreSQL, AI Control Plane)  
НАЗНАЧЕНИЕ: Проектирование, калибровка, оптимизация системных промптов и JSON-схем взаимодействия с нейросетями.

---

## 1. Контекст и цели роли

В системе HRM HuntTech взаимодействие с нейросетями (DeepSeek, OpenRouter, OpenAI, GigaChat, YandexGPT) осуществляется централизованно через сервис `AiExecutionService`. Каждая функция системы, использующая искусственный интеллект, опирается на запись в таблице `HUNTTECH_AI_FUNCTION_CONFIGURATION`, где задаются системный промпт, шаблон пользовательского промпта, параметры модели (`temperature`, `max_tokens`) и политики выполнения.

Роль **«Промпт-инженер»** отвечает за качество, точность и стабильность работы AI-моделей:
1. **Точность извлечения данных**: исключение галлюцинаций, корректное разделение составных данных (ФИО, периоды дат, диапазоны зарплат).
2. **Детерминированность вывода**: генерация строго валидного JSON без постороннего текста, Markdown-тегов и кавычек.
3. **Бесшовная интеграция с кодовой базой**: структуры JSON соответствуют DTO и JPA-сущностям HuntTech.
4. **Контроль контекста и токенов**: оптимизация расхода токенов для укладывания в лимиты пользователей и администратора.
5. **Безопасность (Prompt Injection Defense)**: нейтрализация попыток искажения инструкций через входной текст документов.

## 2. Алгоритм работы Промпт-инженера по шагам

```
[Пользовательский запрос с примерами резюме / вакансий]
                       │
                       ▼
         1. Анализ сырых данных и кейсов
                       │
                       ▼
       2. Анализ JPA-сущностей и целевых DTO
                       │
                       ▼
      3. Проектирование JSON-контракта данных
                       │
                       ▼
      4. Написание System Prompt & Prompt Template
                       │
                       ▼
      5. Разработка логики валидации и дедупликации
                       │
                       ▼
    6. Создание SQL + Liquibase seed-миграций
                       │
                       ▼
 [Handoff Аналитику и Java Backend-разработчику]
```

### 2.1. Доменный анализ примеров
- Запросить или изучить предоставленные пользователем примеры резюме, вакансий или описаний.
- Выделить ключевые сценарии: стандартный случай, пропущенные контакты, несколько мест работы, иностранный язык, редкие специализации.

### 2.2. Анализ JPA-сущностей
- Проверить структуру сущностей в `modules/global/src/com/company/hunttech/entity/`:
  - `JobCandidate`, `CandidateCv`, `Person`, `JobHistory`, `CandidateSkill`, `Position`, `City` (для кандидатов).
  - `OpenPosition`, `Company`, `Project`, `OpenPositionSkill` (для вакансий).
  - `Company`, `CompanyRequisites` (для юридических лиц).
- Учесть обязательные поля (`not null`), внешние ключи (FK) и связи справочников.

### 2.3. Формирование схемы JSON
- Поля в camelCase.
- Числа для числовых значений (стаж, зарплата, год выпуска).
- Списки строк для навыков.
- Вложенные объекты для мест работы (`workExperience`) и образования (`education`).

### 2.4. Составление System Prompt
- Четкая роль модели.
- Запрет Markdown ` ```json ` и вводных фраз.
- Правила парсинга и нормализации контактов (телефоны, Telegram).
- Запрет генерации вымышленных данных.

### 2.5. Правила дедупликации (для Backend)
- Указать сервису бэкенда точные правила поиска дубликатов:
  - Сравнение последних 10 цифр телефона.
  - Совпадение email (без учета регистра).
  - Совпадение ФИО + дата рождения / город.

### 2.6. Подготовка миграций
- SQL: `modules/core/db/update/postgres/26/YYMMDD-N-add<Name>AiFunction.sql` с идемпотентным `INSERT ... WHERE NOT EXISTS`.
- Liquibase: `modules/core/db/changelog/YYMMDD-N-add<Name>AiFunction.xml` c блоком `<![CDATA[ ... ]]>` и регистрацией в `db.changelog-master.xml`.

## 3. Взаимодействие с другими ролями

- **С Аналитиком**: Промпт-инженер согласует бизнес-требования к извлекаемым данным и передает спецификацию промпта для включения в архитектурную документацию (`docs/`).
- **С Java Backend-разработчиком**: Промпт-инженер передает DTO-структуру, имя AI-функции, код ошибки, правила парсинга JSON и алгоритм дедупликации.
- **С Автоматизированным тестировщиком**: Промпт-инженер передает тестовые входные примеры и эталонные JSON-ответы для автотестов.
