# Алгоритм умного создания и открытия вакансий в HRM HuntTech

## 1. Назначение и контекст
Функция умного создания вакансий позволяет рекрутерам, менеджерам и руководству мгновенно преобразовывать произвольные описания вакансий (из писем, мессенджеров, файлов или ссылок в интернете, включая портал `https://need.ssp-soft.com/`) в стандартизированные сущности открытых вакансий `OpenPosition` в HRM HuntTech.

Интерфейсы запуска:
1. **Кнопка «Умная загрузка»** в экранной форме **«Реестр открытых вакансий»** (`OpenPositionReestrBrowse` -> `SmartOpenPositionUploadScreen`).
2. **Интеллектуальный LLM-чат** (`LlmChatService` / `LlmChatScreen`) — перехват текстовых запросов и ссылок.

---

## 2. Разграничение доступа (Security & Governance)
- **В реестре вакансий («Умная загрузка»)**: доступ регламентируется стандартной ролевой моделью CUBA для экрана `OpenPositionReestrBrowse`.
- **В LLM-чате**:
  - Создание вакансий разрешено **строго пользователям из групп «Менеджеры» / «Менеджмент» / «Директор» / «Дирекция»**, пользователям с ролями `Manager`, `Director`, `Administrators`, а также системным администраторам (`admin`, `alan`).
  - Для всех остальных групп пользователей (стажеры, рядовые сотрудники, внешние пользователи) система блокирует операцию и возвращает предупреждение:
    > «Функция открытия вакансий через LLM-чат доступна исключительно пользователям из групп «Менеджеры» и «Директор». У вашей учетной записи недостаточно полномочий для выполнения этого действия.»

---

## 3. Источники данных и способы загрузки
Сервис `SmartOpenPositionIngestService` поддерживает 3 способа загрузки:
1. **Вставка текста**: произвольный текст заявки (включая разметку мессенджеров, блоков `#Проект`, `#Условия`, `#Позиция`, `#Обязательно`, `#Желательно`, `#Задачи`).
2. **Загрузка файлов**: документы форматов `.pdf`, `.docx`, `.doc`, `.rtf`, `.txt` с автоматическим извлечением через `PDFTextStripper` и Apache POI.
3. **Загрузка по ссылке (URL)**:
   - Поддерживаются ссылки на `https://need.ssp-soft.com/details?id=...`, `hh.ru`, `career.habr.com`, корпоративные сайты.
   - Метод `fetchTextFromUrl` выполняет HTTP GET запрос и преобразует HTML в структурированный текст (`convertHtmlToStructuredText`) с сохранением структуры секций, списков и переносов.

## 4. Контракт данных и 4 ключевых артефакта стандарта HuntTech
AI-функция `VACANCY_SMART_PARSE_JSON` и вспомогательный механизм сервиса гарантируют генерацию следующих обязательных блоков:

### 4.1. Стандартизированное описание вакансии (`comment`)
Формируется строго по 14 обязательным разделам стандарта `hunttech-vacancy-opening`:
1. Роль, название должности.
2. Грейд, опыт работы.
3. Описание проекта.
4. Обязанности.
5. Описание требований к вакансии (Хард-скиллы) обязательные.
6. Описание требований к вакансии (Хард-скиллы) желательные.
7. Требования к софт-скиллам.
8. Дополнительная информация (локация, гражданство, оформление).
9. Условия работы (график, удаленка, без разглашения ставок).
10. Список обязательных знаний технологий (сухой список через запятую).
11. Список желательных знаний технологий (сухой список через запятую).
12. Требования к резюме.
13. Собеседование (этапы, тайминг).
14. Рекомендации рекрутеру.

> [!CAUTION]
> **Коммерческая тайна: ставки заказчика**:
> В стандартизированном описании и карточках кандидатов **СТРОГО ЗАПРЕЩЕНО** указывать коммерческую ставку заказчика (числа, T&M, руб/час). В описании фиксируется нейтральная формулировка «Ставка обсуждается индивидуально с успешным кандидатом».

### 4.2. Чек-лист первичного скрининга кандидата (`interviewChecklist`)
Таблица с колонками:
- `Группа навыков` (Опыт и домен, Ключевые технологии, Формат и условия).
- `Конкретный навык / Вопрос для проверки` (проверяемый критерий с проверочным вопросом).
- `Ключевой навык?` (всегда `Да`).
- `Отметка / Примечания рекрутера`.
- `Где искать в резюме?` (разделы и маркеры).

### 4.3. Карта поиска / Инструкция сорсеру (`searchMap`)
- Целевой профиль (роль, грейд, география).
- Готовые поисковые запросы (Boolean Search для Google, HH.ru, LinkedIn).
- Приоритетные компании-доноры кандидатов (системные интеграторы, IT-аутстаффинг, банки).
- Стоп-факторы для первичного скрининга.

### 4.4. План продающего собеседования (`interviewPlan`)
6 структурированных блоков скрипта рекрутера:
1. Введение и презентация компании HuntTech (5–7 мин).
2. Презентация проекта и его уникальности (8–10 мин).
3. Проверка по чек-листу ключевых требований (15–20 мин).
4. Продажа условий работы (5–7 мин).
5. Ответы на вопросы кандидата (5–7 мин).
6. Следующие шаги и фиксация договоренностей (3–5 мин).

## 5. Протокол создания связанных сущностей в БД

### 5.1. Сущность `OpenPosition`
- `vacansyName`: Каноническое наименование по алгоритму `generateCanonicalVacancyName` (`[Grade] [PositionRu] / [PositionEn] ([Project], [City])`).
- `priority`: Устанавливается строго `UNDER_REVIEW` (`-2`), отображается со статусом **«На проверку»**.
- `signDraft`: Устанавливается `true` (черновик, требующий проверки рекрутера перед публикацией).
- `openClose`: `false` (открытая позиция).
- `comment`: 14 разделов стандартизированного описания.
- `interviewChecklist`: чек-лист первичного скрининга.
- `searchMap`: карта поиска сорсера.
- `interviewPlan`: план продающего интервью.
- `rawDescription`: полный исходный текст/запрос.

### 5.2. Сущность `Project`
- Разрешено создавать новую запись в сущности `Project` **только** если открытый проект не найден среди существующих записей в БД по наименованию компании или проекта.
- Если проект существует — вакансия связывается с существующим открытым проектом.

### 5.3. Справочники `Position`, `Grade`, `City`, `SkillTree`
- Новые записи в `Position` (должности) и `City` (города) **НЕ создаются** — подбираются наиболее близкие соответствия из существующих активных справочников системы.
- Навыки сопоставляются со справочником `SkillTree` и связываются через каноническую сущность `OpenPositionSkill` с приоритетом `MAIN`.

### 5.4. Дедупликация вакансий (`findDuplicate`)
Перед созданием вакансии сервис проверяет:
1. Точное совпадение наименования открытой вакансии.
2. Совпадение открытого проекта и должности (`projectName` + `positionType`).
3. Совпадение идентификатора запроса (например, `ID 62630`, `ID 67451`), если он присутствует в тексте или названии.
Если дубликат найден, в UI выводится диалог подтверждения, а в LLM-чате создание дубликата автоматически блокируется с выводом ссылки на существующую открытую вакансию.
