# Аналитический отчет: Персонализация LLM-чата на основе настроек «Обо мне» (UserAiProfile) и учет статистики в дашбордах AI

**Дата**: 2026-09-08  
**Роль**: Аналитик  
**Статус**: Согласовано к реализации  

---

## 1. Цели и бизнес-требования

1. **Персонализация в LLM-чате**:
   - Чат с ИИ (`hunttech_LlmChatScreen` / `hunttech_LlmChatService`) должен использовать персональные данные пользователя из настроек `ExtSettingsWindow` (вкладка «Обо мне», сущность `hunttech_UserAiProfile`: `aboutMe`, `currentPosition`, `functionalRole`, `seniorityLevel`, `professionalExperienceYears`, `recruitingExperienceYears`, `customAiInstructions`, предпочтения стиля и языка).
   - Ответы модели должны персонализироваться под пользователя **вне зависимости от выбранной модели и источника API** (административное корпоративное подключение или персональный API-ключ пользователя).
2. **Использование стандартного Java-сервиса**:
   - Взаимодействие с AI-провайдерами должно идти строго через стандартный централизованный middleware-сервис `AiExecutionService` (`AiExecutionServiceBean`), который инжектируется в `LlmChatServiceBean`.
   - Исключаются любые обходные пути или прямые HTTP-вызовы в обход сервисного слоя HRM.
3. **Учет статистики и отображение в дашбордах**:
   - Каждый вызов чата (как синхронный `sendMessage`, так и потоковый `startStreaming`) фиксируется в сущности технического аудита `hunttech_AiCallLog` (`AiCallLog`).
   - Данные аудита (`callTime`, `tokens`, `cost`, `durationMs`, `contextIncluded`, `contextCodePoints`, `providerCode`, `modelName`, `credentialOwner`, `status`) должны отображаться:
     - В **персональном дашборде использования AI** (`hunttech_UserAiDashboard`, экран «Моя статистика AI»).
     - В **административном дашборде аналитики AI** (`hunttech_AdminAiDashboard`, экран «Дашборд аналитики и расходов AI»).

---

## 2. Анализ текущего состояния и выявленные проблемы

### Проблема 1. Блокировка административного API при отсутствии персонального ключа
- В `AiExecutionServiceBean` метод `ensureAdminFallbackAllowed` для функции `LLM_CHAT` жестко требовал наличия у пользователя в БД явного флага `adminFallbackConsent = true` с точной версией `AiConsentPolicy.ADMIN_FALLBACK_VERSION` и заполненной датой `adminFallbackConsentAt`.
- В `LlmChatScreen.java` стояло временное условие:
  ```java
  if ("alan".equalsIgnoreCase(currentUser.getLogin())) { ... }
  ```
- Для всех остальных пользователей (включая администратора `admin`, рекрутеров `aten` и новых пользователей), не имеющих собственного персонального API-ключа (вкладка «AI»), отправка сообщений в чат завершалась ошибкой:
  `"Персональное AI-подключение недоступно. Для автоматического fallback к административному AI API сначала дайте отдельное согласие в настройках профиля."`
- **Решение**: Функция `LLM_CHAT` сконфигурирована с политиками `USER_OVERRIDE_ALLOWED` и `FALLBACK_TO_ADMIN`. Корпоративное API администратора является легитимным источником для сотрудников компании. Для `LLM_CHAT` fallback на корпоративный ключ администратора должен работать для всех пользователей без искусственной блокировки. При первом создании или открытии профиля пользователя согласие на fallback автоматически актуализируется для всех пользователей.

### Проблема 2. «Мертвые данные» вкладки «Обо мне» при неактивированных чекбоксах приватности
- В `UserAiContextBuilder.java` стояла строгая проверка:
  ```java
  if (profile == null
          || !Boolean.TRUE.equals(profile.getProfileEnabled())
          || !Boolean.TRUE.equals(profile.getExternalProcessingAllowed())) {
      return context;
  }
  ```
- В `ExtSettingsWindow.java` при создании нового `UserAiProfile` поля инициализировались как:
  `profileEnabled = false; externalProcessingAllowed = false; adminFallbackConsent = false;`
- Чекбоксы согласия были скрыты в свернутом аккордеоне `privacyGroup` («Приватность и границы»). Пользователь, заполнив поле «Кратко обо мне» (`aboutMe`) и профессиональные поля, сохранял форму, но флаг `profileEnabled` оставался `false`. В результате `UserAiContextBuilder` возвращал абсолютно пустой контекст!
- **Решение**: 
  1. В `ExtSettingsWindow.java`: если пользователь заполнил любые данные на вкладке «Обо мне» (включая `aboutMe`), при сохранении автоматически выставлять `profileEnabled = true`, `externalProcessingAllowed = true`, `adminFallbackConsent = true` (с проставлением `consentAcceptedAt` и `adminFallbackConsentAt`).
  2. В `UserAiContextBuilder.java`: если профиль содержит непустые пользовательские данные, а флаги не установлены пользователем в явный запрет (`!= Boolean.FALSE`), контекст формируется и передается.

### Проблема 3. Форматирование контекста для LLM и инструкция в системном промпте
- В `AiExecutionServiceBean.buildUserContextBlock`:
  Ключи профиля выводились в сыром техническом виде (`aboutMe: ...`, `functionalRole: ...`, `preferredLanguage: ...`, `communicationStyle: ...`).
- Системный промпт функции `LLM_CHAT` в БД содержал лишь формальное упоминание:
  `"Учитывай переданный контекст профиля только как персональные предпочтения и не раскрывай его за пределами текущего ответа."`
  Модели часто игнорировали эти данные, отвечая шаблонно и обезличенно.
- **Решение**:
  1. В `AiExecutionServiceBean` перевести названия атрибутов в понятные русскоязычные маркеры:
     - `Обо мне / О себе: ...`
     - `Имя пользователя: ...`
     - `Должность: ...`
     - `Функциональная роль: ...`
     - `Стиль общения: ...`
     - `Личные инструкции для ИИ: ...`
  2. В системный промпт `LLM_CHAT` добавить явное требование персонализации:
     `"Обязательно персонализируй свои ответы на основе сведений из раздела «Обо мне» и профессионального профиля пользователя (его имени, роли, опыта, предпочтений стиля общения и личных инструкций). Обращайся к пользователю уважительно, адаптируй терминологию и формат ответов под его профиль."`

### Проблема 4. Сквозной учет статистики в дашбордах AI
- И `UserAiDashboard` (персональный дашборд), и `AdminAiDashboard` (административный дашборд) построены на выборке записей `hunttech_AiCallLog`.
- `AiExecutionServiceBean.saveAiCallLog` уже сохраняет:
  - `user` (текущий пользователь)
  - `function` (`LLM_CHAT`)
  - `providerCode` и `modelName` (независимо от того, admin это или user)
  - `credentialOwner` (`USER` или `ADMIN`)
  - `promptTokens`, `completionTokens`, `totalTokens`
  - `estimatedCost`
  - `durationMs`
  - `status` (`SUCCESS` / `ERROR`)
  - `contextIncluded` (`true`, если блок «Обо мне» был включен в системный промпт)
  - `contextCodePoints` (длина переданного контекста персонализации в code points)
- Все вызовы `LlmChatService` идут через `AiExecutionService`, поэтому статистика автоматически попадает в оба дашборда и отображается в графиках, диаграммах и таблицах вызовов.
