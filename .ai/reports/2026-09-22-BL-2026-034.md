# BL-2026-034 — отчёт реализации

Дата: 2026-09-22

## Scope

Разделены безопасные профили подключения CUBA/JNDI для LOCAL, TEST и
PRODUCTION. Production guard выполняется до SSH/backup/deploy; production и
данные не изменялись.

## Подтверждённые источники

- CUBA использует JNDI `jdbc/CubaDS`.
- JDBC context дублировался в core Tomcat, Jetty и WAR-конфигурациях.
- Gradle `createDb/updateDb` и локальный launcher имели loopback fallback.
- Production target из существующего runbook — loopback и database `hunttech`.

## Ограничения

Реквизиты TEST и пароль/сетевой доступ LOCAL к `192.168.1.135` не подтверждены.
Поэтому добавлены контракт и guard, но не выполнялись сетевой тест, data
transfer, production deployment или production credentials.

## Проверки

```text
bash scripts/test-db-profiles.sh
bash -n scripts/db-profile.sh scripts/validate-db-profile.sh scripts/render-db-context.sh scripts/test-db-profiles.sh scripts/start-app.sh deploy-prod.sh deployment/production-deployment/scripts/build-production-artifact.sh deployment/production-deployment/scripts/deploy-hrm-disabled.sh deployment/production-deployment/scripts/start-hrm-restricted.sh
bash deployment/production-deployment/validation/validate-deployment.sh
```

Секреты и полные secret-bearing JDBC URL в отчёт не включаются.

## PCR/OCR

Локальный static/security review и shell checks выполнены. Внешний `ocr review`
не запускался: политикой безопасности заблокирована передача staged diff и
бизнес-контекста во внешний review-сервис без отдельного доверенного разрешения.
Это ограничение процесса, а не результат `PASS` внешнего OCR; production deploy
и PR не должны считаться подтверждёнными этим сервисом.
