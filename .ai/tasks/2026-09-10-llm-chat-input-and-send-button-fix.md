# Исправление ввода пробелов, отправки по Enter и масштабирования пиктограммы кнопки в LLM-chat

## 1. Основание и цели задачи
**Роль:** Аналитик  
**Дата:** 2026-09-10  
**Запрос пользователя:**
> Ввожу текст в LLM-chat. При вводе текста в строку вводе
> 1. не работают пробелы. То есть нажимаю пробел для вставки между словами и ничего не происходит
> 2. не работает отправка сообщения по кнопку Enter из этой строки ввода.
> 3. на кнопку отправить сообщения размести тематическую пиктограмму в размер кнопки.
> Исправь. Не используй CDP и не передеплой без особого распорядения

## 2. Анализ причин неисправностей

### 2.1. Проблема с пробелами (п. 1)
- **Причина**: В `LlmChatScreen.java` для поля `inputArea` был включен режим `ValueChangeMode.EAGER` без отключения тримминга:
  - Компонент `TextArea` в CUBA Platform по умолчанию имеет `trimming = true` (`WebAbstractTextArea.java: protected boolean trimming = true`).
  - При каждом нажатии клавиши (включая пробел) в режиме `EAGER` на сервер отправлялось значение поля.
  - Метод `convertToModel(componentRawValue)` вызывал `StringUtils.trimToNull(value)`, который безжалостно срезал концевые пробелы (`"слово "` -> `"слово"`).
  - Сервер синхронизировал усеченное значение обратно в браузер клиента, мгновенно стирая введенный пользователем пробел.
- **Решение**:
  - Вызвать `inputArea.setTrimming(false)` в контроллере `LlmChatScreen`.
  - Перевести режим `ValueChangeMode` из `EAGER` в `TIMEOUT` (300 мс), устраняя избыточные roundtrip-запросы на каждый символ и предотвращая фризы ввода при быстром наборе текста.

### 2.2. Проблема с отправкой по Enter (п. 2)
- **Причина**:
  - Серверный `vTextArea.addShortcutListener(...)` на `KeyCode.ENTER` не срабатывал, так как клиентский виджет Vaadin `VTextArea.EnterDownHandler` при нажатии `Enter` без клавиш-модификаторов принудительно вызывает `event.stopPropagation()`, предотвращая всплытие события к обработчику ярлыков.
  - Клиентский JS-скрипт искал элемент по селектору `.llm-chat-input-area textarea`. Однако в CUBA класс `llm-chat-input-area` вешается непосредственно на сам тег `<textarea>` (`<textarea class="v-textarea ... llm-chat-input-area">`), а не на родительский контейнер. Селектор возвращал `null`, и обработчик клавиатуры не подключался вовсе.
  - При отправке через `Button.ClickEvent` существовала вероятность задержки синхронизации значения из `inputArea`.
- **Решение**:
  - Зарегистрировать в `com.vaadin.ui.JavaScript` RPC-функцию `hunttechSendChatMessage(messageText)`.
  - Внедрить через `document.addEventListener('keydown', ..., true)` (фаза перехвата capture) глобальный делегированный обработчик, отслеживающий `Enter` (без Shift/Ctrl/Alt/Meta) в полях ввода чата.
  - При нажатии `Enter`: предотвратить стандартный перенос строки (`e.preventDefault()`, `e.stopPropagation()`), забрать текущее фактическое значение `target.value`, очистить поле и вызвать `window.hunttechSendChatMessage(text)`.
  - Поддержать `Shift+Enter` для штатного переноса строки в многострочном сообщении.
  - Добавить делегированный обработчик клика на кнопку отправки для прямой передачи актуального текста из DOM без гонок синхронизации.

### 2.3. Проблема с масштабом пиктограммы на кнопке отправки (п. 3)
- **Причина**:
  - Кнопка отправки имеет размеры 44x44px.
  - Пиктограмма SVG была жестко задана размером 20x20px (как в коде кнопки, так и в стилях `.llm-chat-send-svg`), занимая менее половины диаметра кнопки и выглядя мелкой и потерянной.
- **Решение**:
  - Смасштабировать тематическую пиктограмму (самолетик Telegram/send) до 30x30px (`width="30" height="30"`, `width: 30px !important; height: 30px !important;`).
  - Обеспечить центрирование в `.v-button-wrap` и `.v-button-caption` с `width: 100%`, `height: 100%`.
  - Актуализировать правила во всех 7 темах оформления системы (`halo`, `havana`, `helium`, `hover`, `hunttech-modern`, `hunttech-modern-dark`, `hunttech-modern-light`) как в `.scss`, так и в скомпилированных `.css`.
  - Скорректировать CSS-селекторы `.llm-chat-input-area` под реальную структуру DOM (на самом элементе `<textarea>`).
