## 1. Scope и границы задачи (Руководитель проектов)

### Цель задачи
Обеспечить корректный, отказоустойчивый и прозрачный AI-подбор кандидатов из вакансии (`OpenPositionReestrBrowse` -> sidebar -> «Подобрать кандидата» -> `CandidateVacancyMatchScreen`) в строгом соответствии с уточненным алгоритмом руководителя от 2026-09-24:
1. Определение и сопоставление должностей вакансии:
   - Использование основных и вспомогательных должностей из карты поиска вакансии.
   - Если карта поиска не задает должности — AI-генерация подходящих должностей.
   - Обязательное точное сопоставление каждой должности со справочником `Position` (никаких произвольных AI-строк в качестве должностей; безопасное поведение при отсутствии совпадений).
2. Выбор и ранжирование кандидатов:
   - Выборка из `JobCandidate` с учетом существующих правил доступности/исключения HRM.
   - AI-ранжирование по критериям:
     * Актуальность / давность работы с кандидатом (в работе месяц > полгода > год > 2-3+ года).
     * Предметная область последнего места работы и соответствие вакансии (максимальный вес).
     * Сеньорность по релевантному опыту (>5 лет Senior, >3 лет Middle, >1 года Junior).
     * Руководящий опыт (если вакансия требует Lead/Руководителя; подтверждается по резюме).
     * Навыки (сопоставление навыков кандидата с навыками вакансии — следующий по значимости вес после предметной области последнего места работы).
3. Использование данных последнего резюме:
   - Определение последнего резюме по дате загрузки.
   - Порядок источников:
     1. оригинальный файл резюме (если есть);
     2. `textCV` (если оригинального файла нет);
     3. чек-лист кандидата;
     4. сопроводительное письмо из резюме (если есть).
   - Не придумывать отсутствующий в источниках опыт.
4. Отказоустойчивость и безопасность:
   - Безопасная обработка пустых CV, отсутствия сопоставления с `Position`, пустых выборок, таймаутов, частичных сбоев.
   - Прозрачные понятные статусы и operationId в UI, отсутствие утечек PII, промптов и секретов в логах.

### Запрещенные действия (Forbidden Scope)

## 2. Реализация и доказательства

### Изменения в коде:
1. `modules/core/src/com/company/hunttech/service/CandidateVacancyMatchAiServiceBean.java`:
   - `resolveVacancyPositions(OpenPosition vacancy, UUID operationId)`: извлекает основные и альтернативные должности из `searchMap` с помощью `extractPositionsFromSearchMap(searchMap, titles)`. При отсутствии — AI-генерация гипотез должностей (`generatePositionsWithAi`).
   - `matchExactPositionInDictionary(String rawTitle)`: сопоставляет названия со справочником `hunttech_Position` (точное совпадение без учета регистра, очистка грейдов Senior/Middle/Junior/Lead, префиксный поиск). Исключает использование произвольных AI-строк в качестве должностей. При отсутствии совпадений безопасный fallback: `vacancy.getPositionType()`.
   - `buildCandidateResumeText(List<CandidateCV> cvList)`: реализует строгую иерархию источников последнего резюме (1. файл резюме через `extractFileTextSafely` / PDFBox & POI, 2. `textCV`, 3. чек-лист / заметки рекрутера `commentLetter`, 4. сопроводительное письмо `letter`). Если текст отсутствует во всех источниках, возвращает защитный маркер для AI.
   - `resolveRecruiterActivityDescription(UUID candidateId)`: вычисляет давность взаимодействий с кандидатом по `IteractionList.dateIteraction` (≤30 дн. — наивысшая актуальность, ≤180 дн. — высокая, ≤365 дн. — средняя, >2-3 лет — низкий приоритет).
   - `resolveLastJobDomainDescription(JobCandidate candidate)`: извлекает сферу и обязанности последнего места работы по `JobHistory` и компании для максимального веса в ранжировании.
2. `modules/core/test/com/company/hunttech/service/CandidateVacancyMatchPositionsAndRankingTest.java`:
   - 5 автоматических модульных тестов: извлечение должностей из HTML карты поиска, точное сопоставление со справочником `Position` с очисткой грейдов, строгий приоритет источников резюме (файл > textCV > чек-лист/заметки > сопроводительное письмо), шкала давности взаимодействий рекрутера, безопасная обработка закрытой вакансии.
3. `docs/services/CandidateVacancyMatchAiService.md`:
   - Обновлена спецификация сервиса, задокументирован обратный сценарий `matchCandidatesForVacancy` и новые тесты.
