Ниже — техническое задание и контракт для интеграции страницы «Работа в ХантТек» (/careers) сайта hunttech.ru с HRM HuntTech (система управления рекрутингом компании). Задача: сайт получает актуальный список открытых вакансий напрямую из HRM и показывает их на странице вакансий.

================================================================
1. ЦЕЛЬ
================================================================
Страница /careers должна получать список открытых вакансий из HRM HuntTech по REST API. Сейчас сайт берёт вакансии из собственной CMS (эндпоинт /api/vacancies) — их необходимо заменить/дополнить источником из HRM, сохранив текущий дизайн карточек.

HRM — единственный источник правды: вакансии заводит и закрывает рекрутёр в HRM. Закрытие вакансии в HRM должно убирать её с сайта в течение 1–5 минут (без ручных действий).

================================================================
2. ОБЩАЯ СХЕМА
================================================================
Сайт (серверная часть, Next.js) сам запрашивает данные из HRM при каждом рендере страницы или по TTL-кешу:

  [Next.js /careers]  --OAuth2-->  [HRM HuntTech REST API]
        ^                                  |
        +---------- JSON-список -----------+

- Протокол: HTTPS/HTTP, JSON (UTF-8)
- Аутентификация: OAuth2 (password grant) + refresh_token
- Доступ: только чтение (read-only)
- Рекомендуемый паттерн для Next.js: ISR с revalidate=300 (см. раздел 9)

================================================================
3. АДРЕС И ДОСТУПЫ
================================================================
Base URL (продуктивный):
  http://hr.hunttech.ru:8080/hrm/rest/v2

ВАЖНО: путь именно /rest/v2 (не /api/v2). Если потребуется доступ по https или через публичный домен — согласовать с администратором HRM.

Доступы (client_id, client_secret, username, password) выдаёт администратор HRM HuntTech отдельным сообщением (технический пользователь, права только на чтение вакансий и справочников). Секреты храните в переменных окружения сервера, не в клиентском коде и не в git.

================================================================
4. АУТЕНТИФИКАЦИЯ (OAuth2)
================================================================
4.1. Получение токена (grant_type=password):

POST {base}/oauth/token
Authorization: Basic base64(<client_id>:<client_secret>)
Content-Type: application/x-www-form-urlencoded

Тело (form-urlencoded):
  grant_type=password&username=<username>&password=<password>

Пример curl:
  curl -X POST "http://hr.hunttech.ru:8080/hrm/rest/v2/oauth/token" \
    -H "Authorization: Basic <base64(client_id:client_secret)>" \
    -H "Content-Type: application/x-www-form-urlencoded" \
    -d "grant_type=password&username=<username>&password=<password>"

Ответ (JSON):
  {
    "access_token": "...",
    "token_type": "bearer",
    "refresh_token": "...",
    "expires_in": 3599,
    "scope": "rest-api"
  }

4.2. Продление токена (когда access_token истёк):

POST {base}/oauth/token
Authorization: Basic base64(<client_id>:<client_secret>)
Content-Type: application/x-www-form-urlencoded

Тело:
  grant_type=refresh_token&refresh_token=<refresh_token>

4.3. Все последующие запросы отправляются с заголовком:
  Authorization: Bearer <access_token>

Примечание: токены хранятся в памяти сервера HRM — после перезапуска сервера старые токены становятся недействительными. Обработайте 401: перезапросить токен (пароль или refresh_token) и повторить запрос один раз.

6. ПОЛЯ ВАКАНСИИ
================================================================
| Поле | Тип | Описание |
| id | string (UUID) | Идентификатор записи |
| _instanceName | string | Краткое название (для отображения) |
| vacansyName | string | Название вакансии |
| vacansyID | string | Внешний код вакансии (может отсутствовать) |
| shortDescription | string | Краткое описание (может отсутствовать) |
| comment | string | Полное описание вакансии (LOB; может отсутствовать) |
| salaryMin / salaryMax | number | Вилка зарплаты, руб. (могут отсутствовать) |
| remoteWork | number | Формат работы: -1 «Не определено», 0 «Офис», 1 «Удалёнка», 2 «Гибрид» |
| remoteComment | string | Комментарий к формату работы (может отсутствовать) |
| workExperience | number | Требуемый опыт, лет (может отсутствовать) |
| commandCandidate | number | Опыт руководства командой (может отсутствовать) |
| closingDate | string (YYYY-MM-DD) | Дата закрытия (может отсутствовать) |
| grade | object {id, _instanceName} | Грейд (Middle, Senior…) |
| cityPosition | object {id, _instanceName} | Город |
| positionType | object {id, _instanceName} | Должность/направление |
| projectName | object {id, _instanceName} | Проект/подразделение |
| skillsList | array of {id, _instanceName} | Навыки/технологии |

Важно:
- Все вакансии в ответе уже отфильтрованы: открытые, не черновики, не внутренние проекты. Сайту не нужно знать про статусы.
- Атрибуты со значением null НЕ включаются в JSON — отсутствие ключа означает null (например, у вакансии без зарплаты нет ключей salaryMin/salaryMax).
- Записи, удалённые в HRM (soft-delete), в выдачу не попадают автоматически.

================================================================
8. ОШИБКИ
================================================================
| HTTP | Причина | Действие сайта |
| 401 | токен истёк/невалиден | перезапросить токен, повторить запрос 1 раз |
| 403 | нет прав на сущность/атрибут | обратиться к администратору HRM |
| 404 | неверный путь/имя запроса | проверить base URL и имена запросов |
| 500 | ошибка сервера | повторить с задержкой (2–3 попытки) |

================================================================
9. РЕКОМЕНДАЦИИ ПО ИНТЕГРАЦИИ (стек сайта)
================================================================
- Вызывайте API только на сервере (server-side): секреты и токен не должны попадать в браузер (CORS не требуется, доступ server-to-server).
- Next.js ISR: revalidate = 300 (5 минут) — актуальность списка без собственного кеша. Можно 60, если важна свежесть.
- При первом 401 после рестарта HRM — автоматически перезапросить токен и повторить запрос.
- Переключите источник страницы /careers с /api/vacancies (ваша CMS) на описанный выше REST-запрос. Дизайн карточек и страницы сохраняется.
- Отсутствующие ключи (описание, зарплата, дата закрытия) трактуйте как null — на карточке можно показывать «по запросу»/скрывать.
- Сетевая доступность: сервер сайта должен иметь доступ к http://hr.hunttech.ru:8080 (уточнить при настройке).

================================================================
10. ЧТО НЕ ВХОДИТ В КОНТРАКТ
================================================================
Через REST не отдаются внутренние данные HRM: финансовые условия (ставки, комиссии, налоги), комментарии рекрутёров, планы/чеклисты интервью, файлы, поисковые карты. Запросы с попыткой получить эти данные вернут ошибку прав (403).
