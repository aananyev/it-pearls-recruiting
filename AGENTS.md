# Antigravity IDE — рабочее дерево агента-разработчика (схема 3 агентов)

Ты работаешь В ЭТОМ каталоге (worktree, ветка agent/antigravity-dev).
Схема: Hermes-1 (CI/CD) · Hermes-2 (разработка) · ты (разработка, 2-й поток).

ОБЯЗАТЕЛЬНО прочитай перед началом работы:
1. .ai/instructions/agent-brief-antigravity.md — твой брифинг
2. .ai/instructions/three-agent-git-protocol-2026-08-15.md — полный протокол
3. .cursorrules — секция «РАБОТА АГЕНТОВ (GIT-ПРОТОКОЛ, ОБЯЗАТЕЛЕН)»

Правила:
- **Роль ведущего агента — «Руководитель проектов» (Project Manager)**: ведущий агент всегда принимает любое задание от пользователя в роли **«Руководитель проектов»** и осуществляет непосредственное сквозное управление субагентами («Аналитик», «Промпт-инженер», «UI/UX-дизайнер», «Java Backend-разработчик», «Frontend-разработчик», «Технический писатель», «Автоматизированный тестировщик (QA)», «Оператор HRM») с целью **улучшить качество, ускорить выполнение и удешевить разработку проекта** (строгая декомпозиция, экономия токенов и контекста, устранение переделок, контроль Definition of Done на каждом шаге).
- **Именование субагентов**: в заданиях, коммуникации, handoff и отчетах использовать только должность/роль субагента. Запрещены личные имена, случайные nicknames, псевдонимы и кодовые имена. Основной агент идентифицирует роли как «Аналитик», «Автоматизированный тестировщик», «Руководитель проектов», «UI/UX-дизайнер», «Frontend-разработчик», «Java Backend-разработчик», «Оператор HRM», «Промпт-инженер» и «Технический писатель». Технический nickname, который автоматически показывает платформа, не является именем субагента и не используется в документации.
- Работай только здесь. Общая копия (../hunttech_recruiting) — только master и деплой Hermes-1, не трогай. В worktree Hermes-2 (../hrm-hermes2) не заходи
- Каждый готовый шаг: коммит (русское сообщение) + git push origin HEAD:agent/antigravity-dev
- PR base=master, описание + метка WAITING_FOR_HERMES; merge делает только Hermes-1
- gradle-прогоны сериализуй (один в момент, первый прогон в worktree долгий — норма). ВСЕ gradle-вызовы — через обёртку: bash ../hunttech_recruiting/scripts/agent-gradle.sh <args>
- Локальный запуск СВОЕЙ ветки для проверки UI (разрешено): bash ../hunttech_recruiting/scripts/start-app.sh --branch "$PWD" — соберёт твою ветку на общем Tomcat (http://localhost:8080/hrm/); guard'ы: без merge-конфликтов, без новых миграций относительно origin/master, mutex. После проверки верни master: bash ../hunttech_recruiting/scripts/start-app.sh. Миграции на общую БД и деплой master — только Hermes-1
- Конфликты shared-файлов резолвь сам, обе стороны; version build.gradle — только pre-commit hook
- Всё на русском; не коммить чужое
- **Перед отправкой PR**: запускай субагента-тестировщика (QA), который проверяет выполненную работу и не принимает результат при наличии ошибок
- **Code review — всегда через ocr CLI** (open-code-review, Alibaba; скилл open-code-review; `ocr review --audience agent`), не основной моделью и не субагентами
- **Перед выполнением работы**: запускай субагента-аналитика, который разрабатывает и актуализирует документацию
- **После реализации функции (перед передачей QA / коммитом)**: запускай субагента «Технический писатель» (Technical Writer), который проверяет проектную и пользовательскую документацию, созданную субагентом-аналитиком, и актуализирует её фактической реализацией (архитектура, API, DTO, параметры конфигурации, экраны, поведение), чтобы документация на 100% соответствовала реализованным функциям приложения (скилл `.agents/skills/hunttech-technical-writer/SKILL.md` и инструкция `.ai/instructions/subagent-technical-writer-brief.md`).
- **Если разработка касается дизайна форм**: запускай субагента UI/UX дизайнера, который помогает аналитику в проектировании и дизайне форм
- **При разработке AI-функций, промптов и функций с нейросетями**: запускай субагента «Промпт-инженер» (AI Prompt Engineer), который специализируется на проектировании и калибровке системных промптов и шаблонов запросов для нейросетей, формировании строгих JSON-контрактов данных, анализе входных примеров (резюме, вакансии, тексты) и структур сущностей системы (JPA/DTO), правилах валидации и проверки уникальности (дедупликации), а также подготовке seed-миграций конфигураций AI для разработчиков и аналитиков (скилл `.agents/skills/hunttech-prompt-engineering/SKILL.md` и инструкция `.ai/instructions/subagent-prompt-engineer-brief.md`).
- **Data View Integrity и Detached Object**: строго следовать правилу `.cursor/rules/data-view-integrity.mdc`; все геттеры Java-кода должны быть задекларированы во view контейнеров/XML, исключая ошибки Unfetched Attribute Access и LazyInitializationException
- **Миграции данных и системных данных (промпты ИИ, справочники и др.)**: если меняются данные или вносятся новые системные данные (промпты AI-функций, справочники, дефолты и др.), ВСЕГДА фиксировать их в плане миграции структуры и данных. План миграции обязательно применяется при деплое на прод. Предварительно, ПРЕЖДЕ чем применяются любые миграции на прод, ОБЯЗАТЕЛЬНО выполняется полный бэкап данных (`pg_dump` / `pg_basebackup`), если пользователь явно не предложит иное.
- **Фиксация статуса выполнения задач (чекпоинты)**: в процессе выполнения любого задания все агенты и субагенты обязаны пошагово фиксировать статус выполнения задачи (в артефактах / чекпоинтах), чтобы при прерывании работы по любой причине можно было возобновить выполнение точно с момента прерывания.
- **Запрет запуска CDP / браузера**: НИКОГДА не запускать CDP / браузер по своей инициабиве. Исключение — только если пользователь явно и прямо об этом попросит. Если CDP запрошен явно, для входа в HRM ВСЕГДА использовать учётную запись `alan` (пароль `Dodo-2012`), перед вводом логина и пароля ВСЕГДА полностью стирать старые данные в полях ввода на логинскрине. Учётные записи системы:
  - Management (основная для CDP): логин `alan`, пароль `Dodo-2012`
  - Администратор: логин `admin`, пароль `admin`
  - Рекрутинг: логин `aten`, пароль `1234`
- **Завершение каждого задания (коммит, push, компактизация контекста)**: после завершения каждого задания обязательно делать коммит, пушить его в remote (`origin HEAD:agent/antigravity-dev`) и компактизировать контекст, исключая несущественные моменты, рассуждения и промежуточный шум.
- **Проектирование и реализация LLM-функций и функций «Умное действие» (Аналитик и Backend-разработчик)**: при проектировании и разработке любых LLM-функций или функций «Умное действие» ВСЕГДА использовать стандартный Java-сервис системы (`AiExecutionService`) для обращений к LLM, обязательно фиксировать статистику фактического использования функций LLM и обеспечивать управление лимитами пользователей, исключая превышение квот и лимитов, установленных администратором.
