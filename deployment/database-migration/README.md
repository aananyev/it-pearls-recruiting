# HRM HuntTech database migration audit

Дата первого этапа: 2026-07-10

## Назначение

Эта папка содержит материалы первого безопасного этапа миграции HRM HuntTech с legacy-модели `itpearls` на модель `hunttech`.

На текущем этапе разрешены только:

- исследование;
- чтение локальных конфигураций;
- read-only запросы к PostgreSQL;
- подготовка документации;
- подготовка read-only SQL-скриптов аудита.

Запрещены:

- изменение production-базы;
- создание объектов на production-сервере;
- остановка HRM;
- запуск миграции;
- DDL или DML на рабочей базе;
- редактирование Java/CUBA/Jmix исходного кода;
- автоматическое исправление найденных проблем.

## Структура

- `audit/` - отчеты аудита и read-only SQL-скрипты.
- `backup/` - место для описания backup-процедур. Дампы и архивы запрещено коммитить.
- `ddl/` - будущие DDL-материалы, пока не используются.
- `migration/` - будущие migration-скрипты, пока не используются.
- `validation/` - будущие проверки миграции.
- `rollback/` - будущие материалы отката.
- `reports/` - риск-регистр и итоговые отчеты. Raw-выводы аудита запрещено коммитить без ручной проверки и маскирования.
- `runbooks/` - пошаговые инструкции для оператора.

## Созданные read-only SQL-скрипты

- `audit/sql/00-instance-architecture-readonly.sql`
- `audit/sql/01-schema-inventory-readonly.sql`
- `audit/sql/02-security-model-readonly.sql`

Все скрипты содержат только `SELECT` и psql-настройки вывода. В них нет `CREATE`, `ALTER`, `DROP`, `INSERT`, `UPDATE`, `DELETE`, `TRUNCATE`, `GRANT`, `REVOKE`.

## Что уже установлено локально

- Проект: CUBA Platform `7.3-SNAPSHOT`.
- JDBC-драйвер: `org.postgresql:postgresql:42.2.9`.
- Локальный PostgreSQL-клиент: `psql 14.20`.
- Локальный сервер PostgreSQL: `PostgreSQL 11.22`.
- Локальная рабочая база новой модели: `hunttech`.
- Локальная legacy-база: `itpearls`.
- Обе локальные базы находятся в `pg_default`; локально `itpearls` и `hunttech` не являются PostgreSQL tablespace.
- На production порт PostgreSQL `hr.hunttech.ru:5432` доступен, но полноценный read-only аудит production не выполнен из-за отсутствия подтвержденных учетных данных и запрета на любые изменения.

## Правило секретов

В Git нельзя сохранять:

- пароли;
- токены;
- приватные ключи;
- raw production-конфигурацию;
- дампы баз;
- персональные данные;
- CSV/TSV выгрузки с production-данными.

В локальных файлах проекта обнаружены секреты. В отчетах они намеренно не раскрываются.

## Правило безопасности других баз данных

На production-сервере `hr.hunttech.ru` могут находиться другие базы PostgreSQL. Они не входят в миграцию HRM HuntTech и считаются неприкосновенными.

Production-миграция должна быть ограничена только явно утвержденной парой баз:

- source: `itpearls`;
- target: `hunttech`.

До запуска реальной миграции скрипты обязаны иметь preflight-защиту от работы в неправильной базе: проверка hostname, port, `current_database()`, source/target DB, пользователя и явной production-фразы подтверждения. Cluster-wide операции (`pg_dumpall --globals-only` restore, роли, grants, tablespaces, restart PostgreSQL, изменения конфигурации кластера) запрещены без отдельного письменного решения.

## Текущий вердикт

`МИГРАЦИЮ НАЧИНАТЬ НЕЛЬЗЯ`

Причина: production-архитектура еще не подтверждена полным read-only аудитом, не выполнены проверенные backup/restore, не утверждены правила преобразования данных и не согласован rollback для записей после переключения.
