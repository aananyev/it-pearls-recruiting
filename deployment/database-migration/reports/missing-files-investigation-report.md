# Stage 2.1. Расследование отсутствующих файлов `sys_file`

Дата: 2026-07-12
Сервер: `hr.hunttech.ru`
База анализа: `hunttech`, созданная на этапе 2 как копия `itpearls`
Статус приложения: Tomcat остановлен, `/app` и `/hrm` не запускались

## Цель

Проверить блокер этапа 2: в таблице `sys_file` есть 633 записи, для которых в CUBA file storage не найден физический файл. Этап 3 не должен начинаться, пока не понятен бизнес-риск и не принято явное решение по каждому классу файлов.

## Ограничения

- База данных не изменялась.
- Production `fileStorage` не изменялся.
- Файлы не удалялись, не создавались и не подменялись.
- Приложение `/hrm` не запускалось.
- Персональные данные, имена файлов, email и содержимое документов в Git не помещались.

## Фактическое хранилище

- `APP_HOME`: `/opt/app_home`
- `cuba.fileStorageDir`: `/opt/app_home/fileStorage`
- Владелец каталога: `tomcat:tomcat`
- Отдельный mount для file storage не используется; каталог находится на `/dev/vda2`.
- Свободное место на момент проверки: около 48G.
- Единственный найденный архив fileStorage: `/var/backups/hunttech-hrm/20260712-175910-stage2-final/fileStorage_20260712-175910.tar.gz`.

## Методика

1. Использован список отсутствующих путей из финальной проверки этапа 2.
2. Для каждого пути выделен UUID `sys_file`.
3. Через read-only SQL проверено наличие записи в `sys_file`.
4. Через read-only SQL просканированы UUID-колонки пользовательских и системных таблиц, чтобы найти ссылки на отсутствующие `sys_file`.
5. Физические файлы искались:
   - по ожидаемому пути в активном `/opt/app_home/fileStorage`;
   - по UUID в других путях активного file storage;
   - по UUID внутри найденных архивов fileStorage без распаковки.

## Результат

- Всего отсутствующих физических файлов: 633.
- Найдено активных бизнес-ссылок: 499 файлов.
- Найдено любых ссылок: 501 файл.
- Найдено в активном file storage по другому пути: 0.
- Найдено в найденных архивах fileStorage: 0.
- Сиротские `sys_file` без ссылок: 132.
- Ссылки только из soft-deleted/archive данных: 2.

## Вывод

Это не косметическая проблема миграции. Для 499 записей есть активные ссылки из данных приложения. Запуск `/hrm` с таким file storage создаёт риск ошибок при открытии резюме, вложений, импортов и очереди полнотекстового поиска.
