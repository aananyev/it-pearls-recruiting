# AI-анализ сущностей HRM HuntTech

> Архитектура · 2026-07-21 · `docs/ai/AI_ANALYSIS.md`

## Назначение и бизнес-смысл

Единая система AI-анализа для любых сущностей рекрутинговой системы HRM HuntTech. Позволяет администратору создавать промпты для нейросетевого анализа, а пользователям — одним кликом получать AI-выводы по резюме, вакансиям, кандидатам и другим объектам.

**Примеры использования:**
- **Анализ резюме:** нейросеть оценивает соответствие кандидата вакансии
- **Расшифровка вакансии:** AI переводит формальное описание на человеческий язык
- **Оценка кандидата:** сводка сильных/слабых сторон по данным карточки
- **Анализ взаимодействий:** выявление паттернов в истории общения с кандидатом

## Архитектура (три слоя)

```
┌─────────────────────────────────────────────────┐
│ UI layer: AiAnalysisAction (кнопка на экране)     │
│ Admin:    AiPromptTemplateBrowse/Edit             │
├─────────────────────────────────────────────────┤
│ Service:  AiAnalysisService.analyze(entity, code) │
│           → загрузка промпта                       │
│           → извлечение данных из сущности           │
│           → подстановка {{placeholders}}           │
│           → вызов AI-провайдера через HrmAiService │
├─────────────────────────────────────────────────┤
│ Entity:   AiPromptTemplate                        │
│           Администратор управляет через CRUD       │
└─────────────────────────────────────────────────┘
```

## Сущности

### AiPromptTemplate

Хранит шаблоны системных промптов. Доступен только администратору.

| Поле | Тип | Описание |
|------|-----|----------|
| `name` | String | Человеческое название («Анализ резюме») |
| `code` | String | Уникальный код (`RESUME_ANALYSIS`) |
| `entityClass` | String | Класс сущности (`com.company.hunttech.entity.CandidateCV`) |
| `promptText` | LOB | Текст промпта с `{{placeholders}}` |
| `description` | String | Описание для администратора |
| `active` | Boolean | Активен ли промпт |

**Placeholders** — переменные в шаблоне, которые заменяются реальными данными сущности.

Для `CandidateCV`:
```
{{resumeText}}          — текст резюме
{{candidateName}}       — ФИО кандидата
{{vacancyDescription}}  — описание привязанной вакансии
{{positionName}}        — название позиции
```

Для `OpenPosition`:
```
{{vacancyDescription}}  — описание вакансии
{{vacancyRequirements}} — требования
{{companyName}}         — название компании
{{projectName}}         — название проекта
```

## Сервис: AiAnalysisService

```
analyze(entity, promptCode) → String (ответ AI)
```

**Алгоритм:**
1. Загружает `AiPromptTemplate` по `code`
2. Извлекает данные из `entity` через зарегистрированные экстракторы
3. Заполняет `promptText`, заменяя `{{placeholders}}` реальными значениями
4. Определяет активного AI-провайдера текущего пользователя
5. Вызывает `provider.generateText(filledPrompt, systemMessage, apiKey, model, params)`
6. Возвращает текст ответа

**Экстракторы данных** регистрируются в Spring-контексте и привязаны к классу сущности:

```java
// Для CandidateCV
registerExtractor("CandidateCV", "resumeText",
    e -> ((CandidateCV) e).getTextCV());
registerExtractor("CandidateCV", "candidateName",
    e -> metadataTools.getInstanceName(((CandidateCV) e).getCandidate()));
```

## UI: AiAnalysisAction

Переиспользуемая кнопка, добавляемая в XML любого экрана:

```xml
<button id="aiAnalysisBtn"
        caption="AI-анализ"
        icon="BRAIN"
        invoke="onAiAnalysisClick"/>
```

Логика в контроллере:
```java
public void onAiAnalysisClick() {
    Entity entity = getEditedEntity();
    String promptCode = resolvePromptCode(entity.getClass());
    String result = aiAnalysisService.analyze(entity, promptCode);
    showResultDialog(result);
}
```

## Администрирование

CRUD-экран `AiPromptTemplateBrowse` / `AiPromptTemplateEdit`:
- Доступен только роли `systemAdministrator`
- Позволяет создавать/редактировать/удалять промпты
- Поле `promptText` — многострочный редактор
- Подсказка с доступными `{{placeholders}}` для выбранной сущности
- Пункт меню: «Администрирование → Системные промпты AI»

## Механика вызова (примеры)

### Анализ резюме на соответствие вакансии

1. Пользователь открывает `CandidateCVEdit` (карточка резюме)
2. Нажимает «AI-анализ»
3. Система находит промпт `code = "RESUME_ANALYSIS"`, `entityClass = "CandidateCV"`
4. Извлекает: текст резюме, ФИО кандидата, описание вакансии
5. Заполняет шаблон:
   ```
   Проанализируй резюме кандидата {{candidateName}}.
   
   Текст резюме:
   {{resumeText}}
   
   Описание вакансии:
   {{vacancyDescription}}
   
   Оцени соответствие кандидата вакансии по шкале 1-10.
   Выдели сильные и слабые стороны. Напиши рекомендации.
   ```
6. Отправляет в AI-провайдера (DeepSeek, OpenAI, etc.)
7. Показывает ответ в модальном диалоге

### Расшифровка вакансии

1. Пользователь в `OpenPositionEdit` нажимает «AI-анализ»
2. Промпт `code = "VACANCY_ANALYSIS"`, `entityClass = "OpenPosition"`
3. AI получает описание вакансии и выдаёт его «расшифровку»:
   - Что реально требуется от кандидата
   - Какие навыки критичны
   - На что обратить внимание при подборе

## Интеграция с существующей инфраструктурой

- **AI-провайдеры:** используются через `HrmAiService` и `AIProviderRegistry` (уже реализованы Codex)
- **API-ключи:** каждый пользователь настраивает свои в окне «Мониторинг ключей пользователя»
- **Безопасность:** промпты доступны только администратору, API-вызовы идут с ключом текущего пользователя
- **Логирование:** опциональный `AiAnalysisLog` для аудита запросов

## Преимущества

- **Расширяемость без кода:** новый тип анализа = новая запись в БД
- **Переиспользование:** одна кнопка на всех экранах
- **Гибкость:** промпты редактируются администратором без пересборки
- **Безопасность:** разделение админских промптов и пользовательских API-ключей
