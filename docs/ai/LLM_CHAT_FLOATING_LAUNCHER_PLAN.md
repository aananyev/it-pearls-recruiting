# Проектировка плавающей кнопки LLM-чата

Дата: 2026-09-06

## Решение

Пункт меню «Чат с ИИ» уже размещён в разделе «Управление AI» и открывает существующий экран `hunttech_LlmChatScreen` в диалоговом режиме. Дополнительный пункт меню не нужен.

Для плавающей кнопки рекомендуется небольшой отдельный визуальный компонент Vaadin 8, подключаемый к overlay/root-слою приложения вне layout `MainScreen`.

## Оценка CUBA 7.3

Штатные средства CUBA подходят для:

- пункта меню;
- обычной кнопки с иконкой и tooltip;
- проверки прав;
- открытия существующего экрана чата.

Для свободного перетаскивания по viewport штатного screen XML/CSS недостаточно. Обычный `Button` с `position: fixed` может быть временным статичным решением, но drag, touch/pointer-события, различение click/drag, ограничение границ и корректный resize лучше реализовать в отдельном лёгком Vaadin-компоненте.

## Архитектура

- Overlay-компонент добавляется к корневому слою приложения, а не внутрь `hbox`/`vbox` MainScreen.
- Клик без перемещения открывает существующий `LlmChatScreen`.
- Перетаскивание не открывает чат.
- Порог начала drag: около 8 px.
- Координаты ограничиваются viewport с безопасными отступами.
- При resize и смене ориентации позиция повторно ограничивается.
- Модальные окна и системные overlay-элементы располагаются выше launcher.
- При отсутствии права на чат компонент полностью не рендерится и не оставляет placeholder.

## Визуальная спецификация

- Круглая тематическая кнопка 52×52 px на desktop, минимум 44×44 px для зоны нажатия.
- Пиктограмма: чат-бабл с AI/spark-акцентом, размер около 24 px.
- Позиция по умолчанию: справа снизу, 24 px от границ; на узком экране — 16 px.
- Состояния: default, hover, focus с кольцом не менее 2 px, pressed, dragging.
- Tooltip и accessible name: «Открыть AI-чат».
- Enter/Space открывают чат; drag не должен быть единственным способом управления.
- При reduced motion отключаются scale/transition-анимации.

## Хранение позиции

Предпочтительный вариант — штатные пользовательские настройки CUBA без миграции: сохранять позицию после `drag-end`, валидировать и ограничивать её при загрузке. При отсутствии подходящего server-side механизма допустим browser storage с namespace приложения и пользователя, но это будет настройка конкретного браузера/устройства.

## Поэтапный план

1. Провести frontend spike: подтвердить точку подключения overlay-компонента в используемом Vaadin 8 widgetset.
2. Реализовать статичный launcher: пиктограмма, tooltip, focus, permission-hidden, click → существующий чат.
3. Добавить drag мышью/тачпадом и pointer/touch-поддержку, порог 8 px, блокировку открытия после drag и viewport clamp.
4. Добавить resize/mobile/safe-area обработку.
5. Добавить сохранение позиции после завершения drag, если штатные пользовательские настройки подходят.
6. Проверить accessibility, темы, модальные окна, переподключение и отсутствие влияния на компоновку MainScreen.

## Приёмка

- Launcher не меняет размеры или расположение элементов MainScreen.
- Обычный клик открывает существующий чат.
- Drag перемещает кнопку и не открывает чат.
- Кнопка остаётся полностью видимой после resize и смены ориентации.
- При отсутствии permission нет кнопки и пустого места.
- Пиктограмма, tooltip, keyboard focus и accessible name работают.
- Модальные окна отображаются поверх launcher.
- Позиция не смешивается между пользователями.

## Ограничения текущего этапа

- Плавающий launcher остаётся временно скрытым до реализации отдельного overlay-компонента.
- Backend, LLM-логика, история и существующий `LlmChatScreen` менять не требуется.
- Точная точка подключения Vaadin overlay и способ server-side сохранения позиции подтверждаются на frontend spike.
