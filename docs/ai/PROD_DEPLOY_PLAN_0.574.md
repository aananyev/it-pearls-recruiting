## 1. Состав релиза 0.574

1. **Функция «Умная загрузка» (заведение карточки кандидата)**:
   - Двухуровневый алгоритм дедупликации кандидатов (по маскированным номерам телефонов, мобильному fallback, Telegram, ФИО с перестановкой).
   - Защита базы от дубликатов в мастере `SmartCvUploadScreen`: приоритет «Не дублировать (привязать резюме к кандидату)», создание дубликата только по явному модальному подтверждению.
   - Очистка кириллических форм собственности компаний (ООО, ПАО, ЗАО, АО, ИП, НКО, Ltd, LLC) с флагом `(?U)`.
   - Поддержка чтения файлов: автоматический zip-fallback для DOCX при несовместимости POI XMLBeans, распознавание RTF-файлов HeadHunter с расширением `.doc` по сигнатуре `{\rtf`, поддержка Apple Pages (`Preview.pdf`).
   - Сохранение фокуса строки в таблицах реестров после завершения умной загрузки.
   - Обновление системного промпта AI для умного парсинга резюме (v3: строгий `null`, атомарные hard skills).

2. **Интеграция с Hermes Agent в LLM-чате**:
   - Полнофункциональное общение с Hermes Agent (`hrm-viewer`) с доступом к базе данных в режиме чтения.
   - Автоматический fallback цепочки моделей (User Configuration -> Admin Configuration -> Container Default).
   - Очистка вывода Hermes от технических кракозябр (UUID / ID видов `"8a0f5f9c-6a32-4e6a-a2c9-672870000001"`, `(ID: ...)`, списочных префиксов).
   - Расширенный резолвер наименований сущностей: вакансии, кандидаты, резюме, компании, взаимодействия, должности (`Position`), навыки (`SkillTree`), проекты (`Project`), пользователи (`ExtUser`), города (`City`).
   - Динамический статус обработки и мгновенное отображение отправленного сообщения.

3. **База данных и миграции**:
   - `260912-1-addPositionIconFields.sql`: колонки пиктограммы должности (`FILE_POSITION_ICON_ID`, `ICON_IMAGE`).
   - `260912-2-addSkillTreeLogoImage.sql`: колонка логотипа компетенции (`LOGO_IMAGE`).
   - `260913-1-addMaxContextTokensToAiConfigs.sql`: колонки `MAX_CONTEXT_TOKENS`, `CONTEXT_RESET_SEQUENCE_NO`.
   - `260913-2-updateSmartCvParsePromptV3.xml`: обновление системного промпта `CV_SMART_PARSE_JSON` до версии 3 с защитой ручных правок администратора.

## 2. Предварительные требования перед деплоем на Production

> [!CAUTION]
> **ОБЯЗАТЕЛЬНЫЙ ШАГ ПО ПРАВИЛАМ СИСТЕМЫ**: Перед накатом любых миграций на production ОБЯЗАТЕЛЬНО выполняется полный бэкап данных через `pg_dump`!

### Команда бэкапа:
```bash
# Выполняется на сервере production (или через Hermes-1):
pg_dump -U postgres -d hunttech -F c -b -v -f "/backup/hunttech_db_pre_0.574_$(date +%Y%m%d_%H%M%S).dump"
```

## 3. Порядок деплоя на Production (выполняет Hermes-1)

1. **Создание Pull Request**:
   - Base: `master`
   - Head: `agent/antigravity-dev`
   - Метка: `WAITING_FOR_HERMES`
   - Название: `Release 0.574: Умная загрузка резюме, дедупликация кандидатов и Hermes Agent`

2. **Merge PR в master** (выполняет только Hermes-1).

3. **Применение миграций БД**:
   ```bash
   ./gradlew updateDb --no-daemon
   ```

4. **Сборка и развертывание на Tomcat production**:
   ```bash
   ./gradlew assemble deploy
   ```

5. **Проверка работоспособности (Healthcheck)**:
   - Проверка доступности URL: `curl -I https://hrm.hunttech.ru/hrm/` (HTTP 200).
   - Проверка вкладки «Hermes Chat» в LLM-чате (успешный ответ агента без технического UUID).
   - Проверка «Умной загрузки» в Реестре кандидатов на тестовом резюме.

---

## 4. План отката (Rollback Strategy)

1. **Если сбой произошёл на этапе сборки/деплоя приложения**:
   - Перезапуск Tomcat с предыдущим артефактом релиза `0.572`.
2. **Если сбой связан с миграциями БД**:
   - Восстановление БД из созданного дампа:
     ```bash
     pg_restore -U postgres -d hunttech -c -v "/backup/hunttech_db_pre_0.574_...dump"
     ```
   - Запуск стабильной версии приложения.
