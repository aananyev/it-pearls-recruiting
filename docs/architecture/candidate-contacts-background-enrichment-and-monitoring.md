# Архитектура и спецификация: Фоновое определение контактных данных и фото кандидатов и Мониторинг

## 1. Назначение и контекст
Подсистема **«Фоновое определение и актуализация контактных данных кандидатов»** (Candidate Contact Enrichment, задача `BL-2026-004`) предназначена для автоматического извлечения и актуализации структурированных контактных данных кандидатов (`JobCandidate`: телефон, мобильный телефон, email, Telegram, Skype, WhatsApp, Viber, город проживания), а также портретной фотографии кандидата из файлов и текстов резюме (`CandidateCV`) с использованием нейросетей (LLM) через централизованный AI Control Plane системы HRM HuntTech.

Инструмент **«Мониторинг фонового определения контактов»** (`hunttech_CandidateContactsEnrichmentMonitoring`) предоставляет администраторам и руководителям полный операционный контроль над фоновым процессом:
- статус работы воркера (активен / остановлен / ожидание);
- сквозные метрики прогресса базы резюме (всего пригодно, обработано, ожидает, найдено контактов, извлечено фото, ошибок);
- аналитика скорости обработки (CV/час) и расчетный ETA до завершения очереди;
- мониторинг расхода токенов и расчетной стоимости вызовов за сегодня;
- история выполнения с детальным логом найденных контактов и дельтой изменений;
- ручное управление: запуск/остановка воркера, ручной повтор (retry) сбойных задач, шаг «Выполнить 1 раз», переключение режима `FREE ONLY`.

## 2. Архитектурная схема и взаимодействие сервисов

```text
[Ручной запуск из UI]                [Фоновый воркер]
 JobCandidateBrowse/Edit     CandidateContactsEnrichmentWorker
         │                                    │
         └───────────────┬────────────────────┘
                         ▼
        CandidateContactEnrichmentService (Orchestrator)
                         │
        ┌────────────────┴────────────────────────────────┐
        │                                                 │
        ▼                                                 ▼
Парсинг оригинала (DOCX/PDF)                  AiExecutionService
- Извлечение картинок (POI/PDFBox)            - Вызов LLM (CONTACTS_EXTRACT_BACKGROUND)
- Фильтрация логотипов (hh, habr)             - Fallback модели при !freeOnly
- Сохранение фото в FileDescriptor            - Экономия токенов (контактная шапка)
  + BLOB в JobCandidate.imageByteArray        - Аудит токенов и стоимости в AiCallLog
        │                                                 │
        └────────────────┬────────────────────────────────┘
                         ▼
             Безопасное сохранение в БД
             - Защита от блокировок (OptimisticLocking)
             - Безопасное слияние (не затирает ручные данные)
             - Фиксация в CandidateCvContactAnalysis
```

### Ключевые сервисы и компоненты:
1. **`CandidateContactEnrichmentService` / `CandidateContactEnrichmentServiceBean`**: единый сервисный слой, выполняющий хэширование резюме (SHA-256), извлечение оригиналов файлов (DOCX, PDF), детекцию фото кандидата с отсечением логотипов, подготовку текстовой шапки, оркестрацию вызова AI вне транзакций БД, безопасное слияние контактов в `JobCandidate` с защитой от блокировок, фиксацию аудита в `CandidateCvContactAnalysis`.
2. **`CandidateCvContactChangedListener`**: слушатель событий изменения сущностей (`EntityChangedEvent<CandidateCV>`), обеспечивающий автоматическую регистрацию новых кандидатов и подгруженных резюме в приоритетную очередь (`priority = 100`) сразу после фиксации транзакции.
3. **`CandidateContactsEnrichmentWorker`**: автономный фоновый планировщик (`ScheduledExecutorService`), гарантирующий:
   - строгую однопоточную обработку (concurrency = 1);
   - троттлинг (настраиваемая пауза `delayBetweenRequestsSec`);
   - почасовые лимиты (`maxCandidatesPerHour`);
   - приоритетную выборку: срочные задачи рекрутеров (`priority >= 100`) обрабатываются в первую очередь;
   - выборку фоновой очереди от свежих к старым (`datePost DESC`);
   - мгновенный триггер обработки (`triggerImmediateProcessing`) при добавлении приоритетных задач;
   - атомарный захват задач через условный UPDATE в БД;
   - автоматическое восстановление зависших задач (`stuckTimeoutMinutes`).
4. **`HunttechContactEnrichmentConfig`**: конфигурационный интерфейс CUBA Platform, сохраняемый в `SYS_CONFIG` с горячим обновлением из UI и админки.
5. **`CandidateContactsEnrichmentMonitoring`**: экран мониторинга в меню «Управление AI» с адаптивными карточками KPI, приоритетной таблицей очереди, фильтрами, бейджами контактов и диалогом детальной дельты.

## 3. Схема состояний (State Machine) резюме

Для каждого анализируемого резюме создаётся и ведётся запись `CandidateCvContactAnalysis`:

| Состояние | Описание |
|---|---|
| `NOT_ANALYZED` (10) | Новое резюме, ожидает первого анализа в очереди |
| `PROCESSING` (20) | Резюме захвачено воркером и находится в процессе обработки |
| `FRESH` (30) | Анализ успешно завершён; хэш содержимого и версия AI совпадают с актуальными |
| `STALE` (40) | Текст резюме изменился либо вышла новая версия AI-функции; требуется повторный анализ |
| `RETRY` (50) | Произошла временная техническая ошибка (429, timeout, блокировка); запланирован повтор |
| `ERROR` (60) | Превышен лимит попыток (`maxRetries`); задача остановлена до вмешательства оператора |
| `SKIPPED` (70) | Текст резюме пуст или непригоден для извлечения контактов |

## 4. Обработка оригинала и детекция фотографии кандидата

### 4.1. Приоритет источников
1. Если к `CandidateCV` прикреплен `originalFileCV` (или `fileCV`):
   - **DOCX**: чтение через Apache POI (`XWPFDocument`), извлечение встроенных изображений (`doc.getAllPictures()`).
   - **PDF**: чтение через PDFBox (`PDFParser`, `PDFTextStripper`), извлечение картинок через `PDResources` / `PDImageXObject`.
   - **DOC / RTF / TXT**: извлечение текстового слоя.
2. Если файл отсутствует, используется текстовое поле `CandidateCV.textCV`.

### 4.2. Алгоритм отсечения логотипов и иконок
В резюме с рекрутинговых сайтов (HeadHunter, Хабр Карьера, SuperJob) часто присутствуют логотипы сервисов, флаги или иконки соцсетей. Для выделения истинного портретного фото кандидата применяются критерии:
- **Минимальный размер**: ширина >= 100 px, высота >= 100 px, общая площадь >= 15 000 px.
- **Соотношение сторон (Aspect Ratio)**: `width / height` строго в диапазоне `[0.60, 1.35]` (портрет или квадрат). Логотипы hh.ru (например 200x40, ratio 5.0) и баннеры автоматически отсекаются.
- **Палитра и формат**: отсечение монохромных изображений и иконок с числом цветов < 16.
- При наличии нескольких подходящих картинок выбирается изображение с наибольшим разрешением в портретном диапазоне.

### 4.3. Двойное хранение фото (требование 11)
Если фото обнаружено и в карточке кандидата отсутствует фотография (`fileImageFace == null && imageByteArray == null`):
1. Фотография сохраняется в стандартное файловое хранилище CUBA через `FileLoader` / `FileUploadingAPI`, и ссылка записывается в `JobCandidate.fileImageFace`.
2. Бинарный массив (`byte[]`) записывается в BLOB-поле `JobCandidate.imageByteArray`.
3. При необходимости фото также дублируется в `CandidateCV.fileImageFace` и `CandidateCV.imageByteArray`.

## 5. Защита от блокировок записи (Optimistic Locking)

В соответствии с требованием 9 учтена ситуация, когда рекрутер держит карточку кандидата открытой в UI:
1. Вызов нейросети выполняется **строго вне транзакций БД**.
2. Изменения в `JobCandidate` сохраняются в короткой изолированной транзакции.
3. Перед обновлением кандидата выполняется `em.refresh(candidate)` для синхронизации версии.
4. **Правило безопасного слияния (Safe Merge)**:
   - Если поле в карточке кандидата уже заполнено вручную рекрутером, а из резюме извлечено пустое значение — существующее значение **никогда не стирается**.
   - Если в карточке поле пустое, а AI обнаружил контакт — поле заполняется.
5. При возникновении `OptimisticLockException` транзакция откатывается, задача переводится в статус `RETRY` с экспоненциальной задержкой (1 мин, 5 мин), что исключает коллизии и потерю данных пользователя.

## 6. Конфигурация (`HunttechContactEnrichmentConfig`)

| Параметр | По умолчанию | Описание |
|---|---|---|
| `hunttech.contactEnrichment.enabled` | `true` | Включение/выключение фонового анализа контактов |
| `hunttech.contactEnrichment.freeOnly` | `true` | Использование строго бесплатных AI-моделей |
| `hunttech.contactEnrichment.delayBetweenRequestsSec` | `15` | Минимальная пауза между запросами к AI (секунды) |
| `hunttech.contactEnrichment.maxCandidatesPerHour` | `60` | Максимальное число резюме, обрабатываемых в час |
| `hunttech.contactEnrichment.maxRetries` | `4` | Максимальное число попыток при сбоях |
| `hunttech.contactEnrichment.batchFetchSize` | `10` | Размер выборки кандидатов из БД |
| `hunttech.contactEnrichment.stuckTimeoutMinutes` | `15` | Таймаут возврата зависших задач в очередь |
| `hunttech.contactEnrichment.aiFunctionCode` | `CONTACTS_EXTRACT_BACKGROUND` | Код AI-функции из каталога Control Plane |
