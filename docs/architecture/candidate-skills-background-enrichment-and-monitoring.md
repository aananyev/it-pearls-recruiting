# Архитектура и спецификация: Фоновое определение навыков кандидатов и Мониторинг

## 1. Назначение и контекст
Подсистема **«Фоновое определение и актуализация навыков кандидатов»** (Candidate Skills Enrichment) предназначена для автоматического постепенного извлечения и актуализации структурированных навыков кандидатов (`CandidateSkill`) по текстам их резюме (`CandidateCV`) с использованием нейросетей (LLM) через централизованный AI Control Plane системы HRM HuntTech.

Инструмент **«Мониторинг фонового определения навыков»** (`hunttech_CandidateSkillsEnrichmentMonitoring`) предоставляет администраторам и руководителям полный операционный контроль над фоновым процессом:
- статус работы воркера (активен / остановлен / ожидание);
- сквозные метрики прогресса базы резюме (всего пригодно, обработано, ожидает, устарело, ошибок);
- аналитика скорости обработки (CV/час) и расчетный ETA до полного завершения очереди;
- мониторинг расхода токенов за сегодня и детекция платных вызовов;
- история выполнения с детализацией изменений навыков (дельта: ADDED, UPDATED, UNCHANGED, SKIPPED);
- ручное управление: запуск/остановка воркера, ручной перезапуск сбойных задач (retry).

## 2. Архитектурная схема и переиспользование сервисов

Подсистема строго разделяет UI-действия и бизнес-сервис, полностью переиспользуя существующий конвейер анализа:

```text
[Ручной запуск из UI]                [Фоновый воркер]
 JobCandidateReestr           CandidateSkillsEnrichmentWorker
        │                                    │
        └───────────────┬────────────────────┘
                        ▼
         CandidateSkillEnrichmentService (Orchestrator)
                        │
                        ▼
               SkillAnalysisService
                        │
                        ▼
               AiExecutionService
                        │
                        ▼
                 AI Control Plane
     (HUNTTECH_AI_FUNCTION_CONFIGURATION:
     SKILLS_EXTRACT_BACKGROUND / SKILLS_EXTRACT)
                        │
                        ▼
                 Provider / LLM
                        │
                        ▼
     Обновление CandidateSkill + Аудит в CandidateCvSkillAnalysis
```

### Ключевые сервисы и компоненты:
1. **`CandidateSkillEnrichmentService` / `CandidateSkillEnrichmentServiceBean`**: единый сервисный слой, выполняющий хэширование резюме (SHA-256), валидацию актуальности, оркестрацию вызова AI вне транзакций БД, применение дельты навыков с сохранением ручных правок, фиксацию аудита и управление приоритетной очередью (`enqueueCandidateCvPriority`).
2. **`CandidateCvChangedListener`**: слушатель событий изменения сущностей (`EntityChangedEvent<CandidateCV>`), обеспечивающий автоматическую регистрацию новых кандидатов и подгруженных резюме в приоритетную очередь (`priority = 100`) сразу после фиксации транзакции.
3. **`CandidateSkillsEnrichmentWorker`**: автономный фоновый планировщик (`ScheduledExecutorService`), гарантирующий:
   - строгую сериализацию (concurrency = 1);
   - троттлинг (настраиваемая пауза `delayBetweenRequestsSec`);
   - почасовые лимиты (`maxCandidatesPerHour`);
   - приоритетную выборку: срочные задачи рекрутеров (`priority >= 100`) обрабатываются в первую очередь;
   - выборку фоновой очереди от свежих к старым (`datePost DESC`);
   - мгновенный триггер обработки (`triggerImmediateProcessing`) при добавлении приоритетных задач;
   - распределённый захват задач через атомарный условный UPDATE в БД;
   - автоматическое восстановление зависших задач (`stuckTimeoutMinutes`).
4. **`HunttechSkillsEnrichmentConfig`**: конфигурационный интерфейс CUBA Platform, сохраняемый в `SYS_CONFIG` с горячим обновлением из UI и админки.
5. **`CandidateSkillsEnrichmentMonitoring`**: экран мониторинга в меню «Управление AI» с адаптивными карточками KPI, приоритетной таблицей очереди (срочные задачи в начале списка), фильтром «В очереди», бейджами «⚡ СРОЧНО» и диалогом детальной дельты.

## 3. Схема состояний (State Machine) резюме

Для каждого анализируемого резюме создаётся и ведётся запись `CandidateCvSkillAnalysis`:

| Состояние | Описание |
|---|---|
| `NOT_ANALYZED` | Новое резюме, ожидает первого анализа в очереди |
| `PROCESSING` | Резюме захвачено воркером и находится в процессе обработки |
| `FRESH` | Анализ успешно завершён; хэш содержимого и версия AI совпадают с актуальными |
| `STALE` | Текст резюме изменился либо вышла новая версия AI-функции; требуется повторный анализ |
| `RETRY` | Произошла временная техническая ошибка (429, timeout); запланирован отложенный повтор |
| `ERROR` | Превышен лимит попыток (`maxRetries`); задача остановлена до вмешательства оператора |
| `SKIPPED` | Текст резюме пуст или непригоден для извлечения навыков |

## 4. Защита данных и политика FREE_ONLY

1. **Сохранение ручных навыков**: навыки с источником `MANUAL` никогда не удаляются и не понижаются в приоритете при AI-обогащении.
2. **FREE_ONLY Policy**: фоновая функция `SKILLS_EXTRACT_BACKGROUND` имеет настройки `executionPolicy = ADMIN_ONLY`, `fallbackPolicy = NO_FALLBACK`. При сбоях провайдера (429/timeout) воркер уходит в отложенный backoff (1м → 5м → 15м → 60м), исключая несанкционированный переход на платные резервные модели.
3. **Двухфазная транзакционная модель**: во время HTTP-запроса к нейросети соединение и транзакция к базе данных **не удерживаются**. Захват и сохранение результата производятся в изолированных ультракоротких транзакциях.
4. **Защита от дублей**: на уровне БД создан уникальный частичный индекс `IDX_CAND_CV_SKILL_ANALYSIS_UNQ_CV (CANDIDATE_CV_ID) WHERE DELETE_TS IS NULL`.

## 5. Конфигурационные параметры (`HunttechSkillsEnrichmentConfig`)

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `hunttech.skillsEnrichment.enabled` | boolean | `true` | Включение/выключение службы фонового анализа |
| `hunttech.skillsEnrichment.freeOnly` | boolean | `true` | Политика использования строго бесплатных AI-моделей |
| `hunttech.skillsEnrichment.delayBetweenRequestsSec` | int | `15` | Минимальная пауза между запросами к AI (секунды) |
| `hunttech.skillsEnrichment.maxCandidatesPerHour` | int | `60` | Максимальное число резюме, обрабатываемых в час |
| `hunttech.skillsEnrichment.maxRetries` | int | `4` | Максимальное число попыток при сбоях AI |
| `hunttech.skillsEnrichment.batchFetchSize` | int | `10` | Размер порции выборки кандидатов из БД |
| `hunttech.skillsEnrichment.stuckTimeoutMinutes` | int | `15` | Таймаут возврата зависших в PROCESSING задач в очередь |
| `hunttech.skillsEnrichment.aiFunctionCode` | String | `SKILLS_EXTRACT_BACKGROUND` | Код AI-функции из каталога Control Plane |
