# AccountingDocumentsHermesBot — внешний бухгалтерский бот Hermes

> Отдельный Telegram-бот для первичных документов и чеков авансового отчета. Бот функционирует в Hermes, не связан со встроенным Telegram-ботом HRM HuntTech и использует AI API, подключенный в Hermes.

## Назначение и бизнес-смысл (What & Why)

`AccountingDocumentsHermesBot` автоматизирует прием сканов первички и чеков авансового отчета без изменения пользовательского сценария: пользователь сканирует документ телефоном и отправляет его в Telegram. Дальше Hermes-бот скачивает новый файл, распознает реквизиты через AI API Hermes, просит подтверждение в Telegram, раскладывает файл в Yandex.Disk и передает учетные данные в HRM HuntTech.

HRM HuntTech в этой архитектуре не запускает бухгалтерского Telegram-бота, не хранит Telegram-токен и не обращается к AI API. HRM HuntTech хранит справочники, реестр `AccountingDocument`, batch отправок и события аудита.

Строго запрещено трогать, удалять, менять, переименовывать, перезаписывать или перемещать уже существующие деловые документы на Yandex.Disk и локальном диске: акты, договоры, УПД, счета, задания, чеки и другие файлы клиентского или бухгалтерского архива. Hermes-бот работает только с новыми файлами, которые пользователь отправил самому боту.

## UI Context & Navigation

Основной интерфейс пользователя — отдельный Telegram-бот `@hrm_hunttech_docs_bot`, работающий в Hermes.

Встроенный HRM Telegram-бот остается отдельным ботом для HRM-команд и не принимает бухгалтерские фото/PDF.

Входные точки Hermes-бота:

| Вход | Назначение |
| --- | --- |
| Фото документа | прием скана с телефона |
| PDF или файл документа | прием готового скана |
| Caption к файлу | подсказка для потока, контрагента, суммы или категории |
| Inline-кнопки | подтверждение, исправление, пометка плохого скана |
| Команды контроля | просмотр очередей, ошибок и ручной запуск отправки |

## Behavior Summary

| Действие | Условие | Результат |
| --- | --- | --- |
| Пользователь отправил файл Hermes-боту | файл является фото или PDF | Hermes скачивает новый файл и сохраняет его во входящую bot-managed зону |
| Hermes распознал документ | AI API вернул реквизиты | Hermes сопоставляет данные со справочниками HRM HuntTech |
| Контрагент найден | есть совпадение с `Company` или `AccountingCompanyAlias` | Hermes отправляет Telegram-карточку подтверждения |
| Контрагент не найден | совпадения нет | документ получает `WAITING_COMPANY_MATCH`, отправка блокируется до ручного выбора |
| Пользователь подтвердил документ | обязательные поля заполнены | Hermes раскладывает файл и обновляет `AccountingDocument` |
| Наступило расписание отправки | есть подтвержденные документы | Hermes отправляет письмо через Yandex.Mail и пишет batch в HRM HuntTech |

## Границы ответственности

| Зона | Владелец | Что делает |
| --- | --- | --- |
| Telegram runtime | Hermes | long polling или webhook, скачивание файлов, ответы и inline-кнопки |
| AI/OCR | Hermes | вызов подключенного AI API, разбор реквизитов, формирование confidence |
| Yandex.Disk | Hermes | запись только новых bot-managed файлов, раскладка после подтверждения |
| Yandex.Mail | Hermes | ежедневная отправка первички и месячная отправка авансового отчета |
| Справочники и реестр | HRM HuntTech | `Company`, `Currency`, `AccountingDocument`, события, получатели, категории |
| Встроенный HRM-бот | HRM HuntTech | вакансии, подписки и другие HRM-команды; бухгалтерские документы не обрабатывает |

## Контракт Hermes → HRM HuntTech

Hermes должен передавать в HRM HuntTech только данные по новым файлам, которыми управляет бот:

| Данные | Обязательность | Комментарий |
| --- | --- | --- |
| `flowType` | обязательно | `PRIMARY` или `ADVANCE_REPORT` |
| `documentType` | желательно | для чеков `RECEIPT` |
| `status` | обязательно | `NEW`, `WAITING_CONFIRMATION`, `WAITING_COMPANY_MATCH`, `READY_TO_SEND`, `SENT`, `ERROR`, `BAD_SCAN` |
| `receivedAt` | обязательно | дата и время получения файла |
| `documentDate` | после распознавания | дата документа или чека |
| `documentNumber` | если есть | номер акта, УПД, счета или договора |
| `company` | если найдено | ссылка на существующий `Company` |
| `recognizedCompanyName` | если распознано | исходное название из документа |
| `recognizedInn` | если распознано | ИНН из документа |
| `amount` | если распознано | сумма документа или чека |
| `currency` | желательно | по умолчанию `RUB` |
| `expenseCategory` | для чеков | категория авансового отчета |
| `originalFileName` | обязательно | имя файла из Telegram |
| `finalFileName` | после раскладки | имя после подтверждения |
| `yandexDiskOriginalPath` | обязательно | путь во входящей bot-managed зоне |
| `yandexDiskFinalPath` | после раскладки | путь в клиентской папке или папке авансового отчета |
| `fileHash` | обязательно | защита от дублей |
| Telegram metadata | обязательно при наличии | chat id, message id, file id, user id |

Каждое значимое действие Hermes фиксирует через `AccountingDocumentEvent`: получение, распознавание, запрос подтверждения, ручное исправление, подтверждение, раскладка, отправка письма, ошибка.

## Использование AI API Hermes

AI API используется только в Hermes-боте:

- извлечь тип документа, дату, номер, сумму, контрагента, ИНН и организацию чека;
- определить поток `PRIMARY` или `ADVANCE_REPORT`;
- предложить категорию чека;
- вернуть структурированный результат с confidence и исходным текстовым объяснением для аудита.

HRM HuntTech не должен получать секрет AI API. В HRM сохраняются только распознанные значения, статус, confidence при необходимости и событие распознавания.

## Минимальный Следующий Этап

Следующий технический этап после этого решения:

1. реализовать Hermes-бот как отдельный процесс с Telegram-токеном и AI API Hermes;
2. подключить запись в HRM HuntTech через согласованный служебный контракт;
3. проверить, что встроенный HRM Telegram-бот не принимает бухгалтерские фото/PDF;
4. выполнить dry-run на тестовой папке `Сканы/_bot_test`;
5. только после подтверждения включать рабочие папки Yandex.Disk.
