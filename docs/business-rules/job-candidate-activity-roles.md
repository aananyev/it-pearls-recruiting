# Бизнес-правила: Определение ролей кандидата в блоке «Последняя активность»

## Назначение

В боковой панели экранов списка кандидатов (`JobCandidateBrowse`, `JobCandidateTestBrowse`, `JobCandidateTest1Browse`) отображается блок **«Последняя активность»**.

Данный блок позволяет рекрутеру мгновенно понять статус кандидата («Свободен» или «В работе») и ответственных сотрудников: **Автор карточки**, **Ресерчер**, **Рекрутер**, **Координатор**.

---

## 1. Алгоритм определения статуса «Свободен»

Кандидат считается **«Свободным»** (`isFree = true`), если выполняется хотя бы одно из условий:
1. У кандидата **нет ни одной записи взаимодействий** в истории (`IteractionList`).
2. Дата последнего зафиксированного взаимодействия была **более 1 месяца назад** (относительно текущей даты).

### Отображение для свободного кандидата:
- Статус: `🟢 Свободен` (зеленый индикатор).
- **Автор карточки**: `👤 Автор карточки: [ФИО / Логин создателя]` (извлекается из системного пользователя `sec$User` по полю `createdBy` кандидата).

---

## 2. Алгоритм определения ролей для активного кандидата («В работе»)

Если кандидат активен (последнее взаимодействие было менее 1 месяца назад), статус выводится как `🔴 В работе` (или дата последней активности), а система анализирует типы взаимодействий (`IteractionList` -> `Iteraction`) для выявления ролей:

| Роль | Критерии определения | Обязанности роли |
| ---- | --------------------- | ---------------- |
| **Ресерчер** | Автор взаимодействия с признаком назначения собеседования `signOurInterviewAssigned == true`, при условии, что собеседование им не проводилось. | Нашел кандидата, зафиксировал первый контакт, назначил интервью, ассистент рекрутера. |
| **Рекрутер** | Автор взаимодействия с признаком проведения внутреннего собеседования `signOurInterview == true` либо зафиксировавший оценку/рейтинг кандидата (`rating != null` / `signFeedback == true`). | Провел собеседование, оценил hard/soft навыки, дал экспертную оценку кандидату. |
| **Координатор** | Автор взаимодействия с признаками отправки резюме клиенту (`signSendToClient == true`), назначения клиентского интервью (`signClientInterview == true`) или вывода на проект (`signStartProject == true`). | Ведет коммуникацию с заказчиком, сопровождает кандидата на этапах у клиента и при выходе на работу. |

---

## 3. Кеширование и оптимизация

- Для исключения N+1 запросов к таблице `SEC_USER` используется локальный кеш логинов/ФИО пользователей.
- Все геттеры взаимодействий (`getRecrutier()`, `getCreatedBy()`, `getDateIteraction()`, флаги типов) задекларированы в соответствующих экранных views (`jobCandidate-browse-view`, `iteractionList-view`), строго соблюдая правила **Data View Integrity**.
