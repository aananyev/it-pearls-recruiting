# Бизнес-правила: Определение ролей кандидата в блоке «Последняя активность»

## Назначение

В боковой панели экранов списка кандидатов (`JobCandidateBrowse`, `JobCandidateTestBrowse`, `JobCandidateReestr`) отображается блок **«Последняя активность»**.

Данный блок позволяет рекрутеру мгновенно понять статус кандидата («Свободен» или «В работе») и ответственных сотрудников: **Автор карточки**, **Ресерчер**, **Рекрутер**, **Координатор**, а также конкретное действие каждого участника процесса.

---

## 1. Алгоритм определения статуса «Свободен»

Кандидат считается **«Свободным»** (`isFree = true`), если выполняется хотя бы одно из условий:
1. У кандидата **нет ни одной записи взаимодействий** в истории (`IteractionList`).
2. Дата последнего зафиксированного взаимодействия была **более 1 месяца назад** (относительно текущей даты).

### Отображение для свободного кандидата:
- Статус: `🟢 Свободен` (зеленый индикатор).
- **Автор карточки**: `👤 Автор: [ФИО создателя] (дата создания)` (извлекается из системного пользователя `sec$User` по полю `createdBy` кандидата).
- **История участников**: Отображает ресерчера и последнего рекрутера, взаимодействовавших с кандидатом ранее, чтобы команда сохраняла преемственность.

---

## 2. Иерархический алгоритм определения ролей («В работе» и архив)

Система последовательно анализирует хронологическую цепочку записей `IteractionList` с учетом специализированных признаков `Iteraction`, групп пользователей `ExtUser.getGroup()` и экспертных оценок:

| Роль | Приоритетные критерии определения | Вторичные критерии (Fallback) | Описание роли |
| ---- | --------------------------------- | ----------------------------- | ------------- |
| **Ресерчер** | 1. `signOurInterviewAssigned == true` (назначено собеседование)<br>2. `signStartCase == true` (взят в работу / первый контакт)<br>3. Пользователь из группы «Ресерчинг», «Ресерчер», «Стажер». | Автор первой записи взаимодействия либо автор создания карточки кандидата. | Сорсинг, первичная валидация контактов, назначение собеседования. |
| **Рекрутер** | 1. `signOurInterview == true` (проведено внутреннее интервью)<br>2. `rating != null` (установлена экспертная оценка/рейтинг)<br>3. `signFeedback == true` (зафиксирован фидбек). | Автор последнего содержательного взаимодействия (не относящийся к группе ресерчинга/менеджмента). | Экспертная оценка soft/hard skills, ведение переговоров с кандидатом. |
| **Координатор** | 1. `signSendToClient == true` (резюме передано заказчику)<br>2. `signClientInterview == true` (интервью у клиента)<br>3. `signStartProject == true` / `signEndProject == true` (выход/завершение проекта). | Сотрудник из группы «Менеджеры», «Координация», «Руководство» или владелец вакансии. | Управление клиентским пайплайном, координация встреч с заказчиком, онбординг. |

---

## 3. Визуальный блок в сайдбаре (`candidate-activity-sidebar`)

Блок выводится на стандартном тёмно-синем фоне сайдбара (`#172638`) без внешних рамок и светлых плашек в едином стиле со смежными секциями («Контакты и реквизиты», «Основные навыки»):

- 🟢/🔴 **Статус кандидата**: светофорный чип-бейдж (`team.status.getLabel()`) с тонкой нижней разделительной линией `1px solid rgba(255, 255, 255, 0.1)`.
- 👤 **Автор**: `ФИО создателя` `(дата создания)` (шрифт `rgba(248, 250, 252, 0.9)` / `rgba(255, 255, 255, 0.45)`).
- 🔍 **Ресерчер**: `ФИО` • `[Действие: Назначено собеседование / Взят в работу / Первичный контакт]`.
- 💼 **Рекрутер**: `ФИО` • `[Действие: Проведено собеседование / Оценка N★]`.
- 🤝 **Координатор**: `ФИО` • `[Действие: Отправлен клиенту / Собеседование у клиента / Выход на проект]`.
- ⏱️ **Посл. активность**: `Дата — [Тип взаимодействия] ([Сотрудник])` (мягкий верхний разделитель `1px dashed rgba(255, 255, 255, 0.12)`).
- **Всего взаимодействий**: `[Число]` (`rgba(255, 255, 255, 0.45)`).

### Оформление шапки кандидата:
- **ФИО (`detailFullName`)**: контрастный яркий белый `#f8fafc` с тенью `text-shadow: 0 1px 3px rgba(0,0,0,0.5)` для отличной читаемости на тёмном фоне.
- **Должность (`detailPosition`)**: светлый бейдж `#93c5fd` на полупрозрачном синем фоне `rgba(59, 130, 246, 0.25)`.
- **Город (`detailCity`)**: мягкий светлый тон `#cbd5e1`.

---

## 4. Data View Integrity и оптимизация

- Локальный потокобезопасный кэш `userFullNameCache` предотвращает N+1 запросы к `sec$User`.
- Все свойства взаимодействий (`iteractionList`, `iteractionType`, `recrutier.group`, `vacancy.owner`, `rating`) задекларированы в экранных представлениях `jobCandidate-view` и `iteractionList-view`.
