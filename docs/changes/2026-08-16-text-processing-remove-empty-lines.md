# 2026-08-16 — Удаление пустых строк при AI-форматировании текста

## Компоненты

- `TextProcessingServiceBean` (`modules/core`) — реализация сервиса умного AI-форматирования.
- `TextProcessingService` (`modules/global`) — интерфейс сервиса (javadoc).
- `TextProcessingServiceBeanTest` (`modules/core/test`) — новые контрактные тесты.

## Назначение

Сервис умного форматирования текста (резюме, сопроводительных писем) теперь гарантированно
удаляет пустые строки в процессе форматирования — независимо от того, что вернула AI-модель
или как выглядел исходный текст.

## Причина

Пустая строка в выводе сервиса превращалась в видимую пустую строку в RichTextArea:
`CandidateCVEdit` заменяет каждый перевод строки результата на `<br>` (`breakLine[0]`).
AI-модель и исходники резюме нередко содержат лишние пустые строки, из-за чего
отформатированный текст выглядел «рваным». Ранее требование «удалять пустые строки»
было только в SYSTEM_PROMPT функции `TEXT_SMART_FORMAT_HTML` (миграция 260816-4) —
без гарантии на уровне кода сервиса.

## Прежнее vs новое поведение

| Аспект | Прежнее | Новое |
|--------|---------|-------|
| AI-HTML результат | чистился только от ```html-обёрток | дополнительно удаляются все пустые строки |
| AI-Plain результат | чистился только от ```-обёрток | дополнительно удаляются все пустые строки |
| Локальный plain-движок | схлопывал пустые строки в одну (оставлял разделители) | пустые строки не переносятся в результат (секции разделяются `═══ … ═══`) |
| Локальный HTML-движок | пустые строки уже пропускались | без изменений |
| Пустой результат после очистки | возвращался пустой AI-результат | используется локальный типографический движок |

## Изменённые файлы

- `modules/core/src/com/company/hunttech/service/TextProcessingServiceBean.java` —
  новый приватный метод `removeEmptyLines`, вызовы в `cleanAiHtmlOutput`/`cleanAiPlainOutput`,
  защита от пустого результата после очистки, локальный plain-движок не переносит пустые строки.
- `modules/global/src/com/company/hunttech/service/TextProcessingService.java` — javadoc
  методов `formatHtml`/`formatPlainText` (контракт удаления пустых строк).
- `modules/core/test/com/company/hunttech/core/TextProcessingServiceBeanTest.java` —
  4 новых теста: AI-HTML, AI-Plain, локальный HTML, локальный Plain — ни одна строка
  результата не пустая.
- `docs/02_business_logic/TextProcessingService.md` — принцип «Удаление пустых строк».

## Ключевые решения

- Удаление пустых строк выполняется **на уровне кода сервиса** (пост-обработка результата),
  а не только через SYSTEM_PROMPT: гарантия не зависит от послушности модели и работает
  одинаково для HTML и Plain Text.
- Удаляются строки из одних пробелов/табуляций (`line.trim().isEmpty()`), а не только
  полностью пустые.
- Если после удаления пустых строк результат пуст (модель вернула одни переносы) —
  сервис откатывается на локальный типографический движок вместо возврата пустого текста.
- Локальный plain-движок больше не оставляет пустых строк-разделителей: читаемость
  обеспечивают заголовки секций `═══ … ═══` и маркеры списков `•`.

## Проверка и откат

- Тест: `./gradlew :app-core:test --tests '*TextProcessingServiceBeanTest'`.
- Ручная проверка: CandidateCVEdit → «Преобразование» → в RichTextArea нет пустых строк.
- Откат: revert коммита (код сервиса без миграций БД — откат безопасен).

## Ограничения

- Пустые абзацы `<p></p>`, которые модель всё же вставит, по-прежнему отсекаются
  требованием SYSTEM_PROMPT (260816-4); код сервиса удаляет именно пустые строки.
- Существующие разделители секций в plain-режиме (`═══ … ═══`) сохраняются.
