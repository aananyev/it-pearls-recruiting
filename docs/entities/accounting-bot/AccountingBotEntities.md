# Бухгалтерский Telegram-бот: сущности

## История изменений

| Дата | Изменение |
| ---- | --------- |
| 2026-07-29 | Зафиксирована модель данных Этапа 1 для хранения первичных документов, чеков авансового отчета, писем отправки, получателей и аудита действий бота. |

## Назначение и бизнес-смысл (What & Why)

Бухгалтерский Telegram-бот автоматизирует прием сканов первичных документов и чеков авансовых отчетов, подтверждение через Telegram, подготовку отправки бухгалтеру через Yandex.Mail и хранение технической истории обработки в HRM HuntTech.

Модель данных добавляет собственный бухгалтерский контур, но переиспользует существующие справочники HRM HuntTech:

| Назначение | Используемая сущность |
| ---------- | --------------------- |
| Контрагент / клиент | `Company` |
| Валюта суммы | `Currency` |
| Пользователь-отправитель | `ExtUser` |
| Договор клиента | `LaborAgreement` |

Новые сущности не заменяют эти справочники и не дублируют их. Они хранят только данные, которые специфичны для процесса бухгалтерского бота.

## UI Context & Navigation

В Этапе 1 пользовательский интерфейс не добавляется. Сущности готовятся для будущих сервисов и административных экранов HRM HuntTech.

Планируемая навигация будущего интерфейса:

| Раздел | Сущности |
| ------ | -------- |
| Бухгалтерия → Документы | `AccountingDocument`, `AccountingDocumentEvent`, `AccountingEmailBatch` |
| Бухгалтерия → Настройки бота | `AccountingAutomationSettings`, `AccountingRecipient` |
| Бухгалтерия → Справочники | `AccountingExpenseCategory`, `AccountingCompanyAlias` |

## Behavior Summary

| Действие | Условие | Результат |
| -------- | ------- | --------- |
| Бот получил скан первички | Файл принят из Telegram | Создается `AccountingDocument` с потоком `PRIMARY` и статусом `NEW` или `WAITING_CONFIRMATION`. |
| Бот получил чек авансового отчета | Файл принят из Telegram | Создается `AccountingDocument` с потоком `ADVANCE_REPORT`, типом `RECEIPT` и категорией расхода при наличии совпадения. |
| Контрагент найден | Есть совпадение по `AccountingCompanyAlias` или `Company` | В документ записывается ссылка на существующую `Company`. |
| Контрагент не найден | Нет надежного совпадения | Документ остается в статусе `WAITING_COMPANY_MATCH`; бот должен запросить подтверждение или выбор контрагента в Telegram. |
| Документ включен в письмо | Наступило дневное или месячное расписание | Создается или обновляется `AccountingEmailBatch`, документ получает ссылку на письмо. |
| Письмо отправлено | Yandex.Mail вернул успешный результат | `AccountingEmailBatch` и связанные документы получают статус `SENT`, фиксируется `sentAt`. |
| Выполнено значимое действие | Статус или файл изменены ботом | Создается `AccountingDocumentEvent` для аудита. |

## Новые Сущности

### `AccountingDocument`

Центральная сущность входящего бухгалтерского документа.

Ключевые поля:

| Поле | Смысл |
| ---- | ----- |
| `flowType` | Поток: первичка или авансовый отчет. |
| `documentType` | Тип документа: договор, акт, УПД, счет, задание, чек, другое. |
| `status` | Текущий статус обработки. |
| `receivedAt` | Когда документ принят ботом. |
| `documentDate`, `documentNumber` | Реквизиты документа после распознавания или ручного подтверждения. |
| `company` | Ссылка на существующую `Company`; новый справочник контрагентов не создается. |
| `recognizedCompanyName`, `recognizedInn` | Сырые данные распознавания для проверки, если контрагент не найден. |
| `amount`, `currency` | Сумма и валюта; валюта ссылается на существующую `Currency`. |
| `expenseCategory` | Категория расхода для чеков авансового отчета. |
| `laborAgreement` | Связанный договор из существующей `LaborAgreement`, если бот сможет определить его надежно. |
| `yandexDiskOriginalPath`, `yandexDiskFinalPath` | Пути на Yandex.Disk. |
| `fileHash` | Технический хеш для поиска повторов. |
| `emailBatch` | Письмо, которым документ отправлен бухгалтеру. |

### `AccountingEmailBatch`

Пакет документов, отправляемый одним письмом через Yandex.Mail.

Для первички пакет формируется один раз в день. Для авансового отчета пакет формируется один раз в месяц в последних числах месяца и отправляется отдельным письмом с фразой `Авансовый отчет` в теме.

### `AccountingDocumentEvent`

Аудит обработки документа. Хранит дату события, тип события, старый и новый статус, источник события и текст сообщения.

### `AccountingExpenseCategory`

Справочник категорий чеков авансового отчета.

Этап 1 предзаполняет категории:

| Код | Наименование |
| --- | ------------ |
| `FUEL` | Топливо |
| `SERVICES` | Услуги |
| `TRANSPORT` | Транспорт |
| `COMMUNICATION` | Связь и интернет |
| `MATERIALS` | Материалы и товары |
| `OTHER` | Другое |

### `AccountingRecipient`

Справочник получателей бухгалтерских писем. Здесь хранится информация о бухгалтерах, которым бот отправляет первичку и авансовые отчеты.

Этап 1 предзаполняет основного получателя для всех потоков:

| Роль | Поток | Email |
| ---- | ----- | ----- |
| Основной бухгалтер | Все потоки | `i.russkova@key-success.ru` |

### `AccountingCompanyAlias`

Связка распознанного названия или ИНН с существующей `Company`. Нужна для случаев, когда в документах контрагент написан иначе, чем в справочнике HRM HuntTech.

Если бот не находит контрагента, он не создает новую `Company` автоматически. Он ставит документ в статус `WAITING_COMPANY_MATCH` и запрашивает подтверждение в Telegram.

### `AccountingAutomationSettings`

Технические настройки бота: имя Telegram-бота, пути Yandex.Disk, расписания отправки и шаблоны тем писем.

Секреты не хранятся в этой сущности:

| Секрет | Где хранить |
| ------ | ----------- |
| Telegram token | Переменная окружения / `.env.local` |
| Yandex.Mail пароль приложения | Переменная окружения / `.env.local` |
| Telegram ID подтверждающего | Локальная настройка окружения или защищенная production-настройка, не в git |

## Миграция

Файл миграции: `modules/core/db/changelog/260729-1-addAccountingBotEntities.xml`.

Миграция:

1. Проверяет наличие существующих таблиц `HUNTTECH_COMPANY`, `HUNTTECH_CURRENCY`, `SEC_USER`, `HUNTTECH_LABOR_AGREEMENT`.
2. Создает только новые таблицы бухгалтерского контура.
3. Добавляет индексы и внешние ключи на существующие справочники.
4. Предзаполняет `RUB`, если такой валюты еще нет.
5. Предзаполняет базовые категории чеков.
6. Предзаполняет основного получателя бухгалтерских писем.

Подробный регламент production-переноса описан в `docs/database/migrations/accounting-bot-preseed-migration-2026-07-29.md`.

## Ограничения Безопасности

Строго запрещено трогать, удалять, переименовывать или изменять уже существующие деловые документы на Yandex.Disk и локальном диске: акты, договоры, УПД, счета, задания, чеки и другие первичные документы.

До отдельного подтвержденного этапа бот может работать только с тестовой зоной `_bot_test` или с новыми файлами, которые пользователь явно отправил боту.
