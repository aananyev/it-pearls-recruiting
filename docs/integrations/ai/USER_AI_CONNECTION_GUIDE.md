# Инструкция пользователя: подключение AI в HuntTech HRM

Документ описывает, как пользователю HuntTech HRM подключить персональный API-ключ нейросети, проверить соединение и подготовить настройки к работе с AI-функциями рекрутинга.

## 1. Что такое персональное AI-подключение

AI-подключение хранит параметры доступа к внешнему API нейросети:

| Поле | Что указать |
|------|-------------|
| Провайдер | Сервис нейросети из списка десяти поддерживаемых подключений |
| API-ключ | Секретный ключ доступа из личного кабинета провайдера |
| Модель по умолчанию | Название модели, если нужно переопределить стандартную модель провайдера |
| Активно | Использовать ли эту конфигурацию в рабочих AI-функциях |

Настройки являются персональными. Один пользователь не видит и не использует API-ключи другого пользователя.

## 2. Где открыть настройки

1. Войдите в HuntTech HRM под своей учётной записью.
2. Откройте окно пользовательских настроек через стандартный пункт настроек пользователя.
3. Перейдите на вкладку `AI`.

На вкладке отображается таблица ваших персональных подключений к AI.

## 3. Как добавить подключение

1. На вкладке `AI` нажмите `Создать`.
2. В поле `Провайдер` выберите нужный сервис.
3. В поле `API-ключ` вставьте ключ из личного кабинета провайдера.
4. При необходимости заполните `Модель по умолчанию`.
5. Убедитесь, что флаг `Активна` включён.
6. Сохраните запись.

После сохранения подключение появится в таблице.

## 4. Поддерживаемые провайдеры

В `SettingWindow` доступны десять реализованных провайдеров. При выборе сервиса поле модели автоматически заполняется рекомендуемым значением, если пользователь ещё не ввёл модель вручную.

| Страна | Провайдер | Код | Модель по умолчанию |
|--------|-----------|-----|----------------------|
| Россия | YandexGPT | `yandex` | `yandexgpt/latest` |
| Россия | GigaChat | `gigachat` | `GigaChat` |
| США | OpenAI | `openai` | `gpt-4o` |
| США | Anthropic Claude | `anthropic` | `claude-sonnet-4-6` |
| США | Google Gemini | `gemini` | `gemini-3.5-flash` |
| США | xAI Grok | `grok` | `grok-4.3` |
| Китай | DeepSeek | `deepseek` | `deepseek-v4-flash` |
| Китай | Alibaba Qwen | `qwen` | `qwen-plus` |
| Китай | Moonshot Kimi | `kimi` | `kimi-k2.5` |
| Китай | Z.AI GLM | `glm` | `glm-5.1` |

### 4.1 Формат поля API-ключ

Для большинства провайдеров в поле `API-ключ` вставляется ключ без дополнительных данных. Исключения связаны с требованиями официальных API:

| Провайдер | Что ввести в поле `API-ключ` |
|-----------|-------------------------------|
| OpenAI, Claude, Gemini, Grok, DeepSeek, Qwen, Kimi, GLM | Обычный API-ключ из кабинета провайдера |
| YandexGPT | `folderId|apiKey`, где `folderId` — идентификатор каталога Yandex Cloud |
| GigaChat для физлица | Ключ авторизации; scope `GIGACHAT_API_PERS` применяется автоматически |
| GigaChat для организации | `GIGACHAT_API_B2B|ключ` или `GIGACHAT_API_CORP|ключ` согласно тарифу |

Для YandexGPT вместо короткого имени модели можно указать полный URI вида `gpt://<folderId>/<model>`. Для GigaChat приложение само получает временный OAuth-токен перед каждым запросом; в настройках сохраняется ключ авторизации, а не временный токен.

Секреты вводятся только через `SettingWindow`. Они не должны попадать в исходный код, SQL-скрипты, документацию или журналы.

## 5. Как проверить подключение

1. На вкладке `AI` выделите строку подключения в таблице.
2. После выбора строки станет доступна кнопка `Тестирование подключения`.
3. Нажмите `Тестирование подключения`.

Приложение выполнит короткий реальный запрос к API выбранного провайдера.

Если всё настроено правильно, появится сообщение:

`Подключение к API нейросети успешно проверено`

Если проверка не пройдёт, появится сообщение:

`Ошибка подключения к API нейросети`

В описании ошибки будет указана причина: не указан API-ключ, провайдер не подключён в приложении, API вернул ошибку авторизации, модель не найдена, сетевой endpoint недоступен и т.п.

## 6. Как редактировать подключение

1. Выделите нужную строку в таблице.
2. Нажмите `Редактировать`.
3. Измените API-ключ, модель или активность.
4. Сохраните запись.
5. При необходимости снова нажмите `Тестирование подключения`.

## 7. Как отключить подключение

Есть два способа:

| Способ | Когда использовать |
|--------|--------------------|
| Снять флаг `Активна` | Если подключение нужно временно отключить, но сохранить параметры |
| Нажать `Удалить` | Если подключение больше не нужно |

Для рабочих AI-функций приложение выбирает активную конфигурацию текущего пользователя для выбранного провайдера.

## 8. Рекомендации по безопасности

- Не передавайте API-ключи другим пользователям.
- Не вставляйте API-ключи в комментарии, задачи, письма и текст вакансий.
- Если ключ был раскрыт, отзовите его в личном кабинете провайдера и создайте новый.
- Для разных пользователей используйте разные API-ключи, если это поддерживается политикой компании.
- После смены ключа обязательно выполните `Тестирование подключения`.

## 9. Частые ошибки

| Сообщение или ситуация | Что проверить |
|------------------------|---------------|
| Не указан API-ключ | Откройте запись и заполните поле `API-ключ` |
| Провайдер AI не подключён в приложении | Выбран код провайдера, для которого нет реализации в системе |
| Ошибка авторизации API | Проверьте, что ключ скопирован полностью и не был отозван |
| Модель не найдена | Проверьте название модели или оставьте поле модели пустым для стандартной модели |
| Пустой ответ API | Повторите тест; если ошибка сохраняется, проверьте ограничения аккаунта провайдера |

## 10. Где администратор видит подключения

Администратор может открыть меню `Управление AI` → `Мониторинг ключей пользователей`.

Экран мониторинга показывает пользователя, провайдера, модель и активность подключения. API-ключи в мониторинге не отображаются.
