# CandidateVacancyMatchAiService

## Назначение и бизнес-смысл (What & Why)

`CandidateVacancyMatchAiService` выполняет AI-анализ соответствия кандидата открытым вакансиям HRM HuntTech. Сервис сопоставляет профиль, резюме и зафиксированные навыки кандидата с требованиями и навыками вакансий, возвращает ранжированный отчёт и даёт экрану фактический прогресс длительной операции.

Фактический прогресс нужен рекрутеру для понимания текущего этапа, объёма уже обработанных вакансий и ожидаемого времени завершения. Процент меняется после реально завершённого аналитического пакета, а не по таймеру.

## UI Context & Navigation

Сервис используется диалогом «Подобрать вакансию», открываемым из карточки или реестра кандидатов. Web-экран заранее создаёт `operationId`, запускает сопоставление в фоновой задаче и опрашивает прогресс через CUBA remote service. Итоговый отчёт остаётся источником данных таблицы подходящих вакансий.

Обратный сценарий подбора кандидатов из вакансии использует `matchCandidatesForVacancy(UUID)` и не зависит от нового polling-контракта.

## Behavior Summary

| Действие | Условие | Результат |
|---|---|---|
| Запуск подбора | Переданы `candidateId` и `operationId` | Создаётся снимок `PREPARING`, затем загружаются кандидат, резюме, навыки и открытые вакансии |
| Отбор вакансий | `openClose = false` или `openClose is null` | В AI-анализ попадают только открытые вакансии; `openClose = true` исключается JPQL и защитным Java-фильтром |
| Анализ пакета | До 12 вакансий и до 40 000 символов контекста | Вызывается существующая AI-функция `CANDIDATE_VACANCY_MATCH_ANALYZE` |
| Диагностика AI-маршрута | Формируется вызов пакета вакансий или отдельного кандидата | Передаются безопасные `callerSource` и `requestId`; профиль, резюме и навыки в технический route log не выводятся |
| Завершение пакета | Ответ AI обработан либо произошла ошибка | Увеличиваются реальные счётчики пакетов и вакансий; ошибка увеличивает `failedChunks` |
| Запрос прогресса | Операция существует и TTL не истёк | Возвращаются процент, текущий статус, счётчики, прошедшее время и ETA |
| Частичный отказ AI | Хотя бы один пакет успешно разобран | Успешные результаты сохраняются, пропущенные вакансии получают нейтральную оценку, прогресс завершается с предупреждением |
| Полный отказ AI | Нет успешно разобранных пакетов | Возвращается существующая честная rule-based оценка |

## Алгоритм сопоставления

Для каждого кандидата используются его профиль, структурированные `CandidateSkill` с приоритетом, основное актуальное резюме и сжатые фрагменты предыдущих резюме. Для каждой открытой вакансии передаются должность, проект, требуемый опыт, грейд, справочные навыки, описание, город и условия удалённой работы. Одинаковый кандидатский набор сравнивается с каждой вакансией, после чего AI возвращает отдельно оценку роли, навыков, опыта, предпочтений и предметной области.

Суммарный score не принимается напрямую из ответа модели: сервис ограничивает каждую составляющую диапазоном её шкалы и складывает значения до 100. Вакансия принимается только если её UUID принадлежит текущему AI-пакету; повторы и посторонние ID исключаются. Результат ранжируется по score, затем по приоритету вакансии и названию. При частичном отказе AI успешные пакеты сохраняются, а неразобранные позиции помечаются «Не оценен AI». При полном отказе применяется явно обозначенный rule-based fallback на основе структурированных и подтверждённых резюме навыков.

Все вакансии проходят анализ пакетами до 12 позиций и лимитом около 40 000 символов контекста. Вакансии с `openClose = true` исключаются до формирования пакетов; `false` и `null` допускаются. На этапе подготовки кандидата экран обновляет навыки только если последнее резюме новее наиболее свежей записи навыков или навыки отсутствуют, поэтому AI получает актуальный сохранённый набор.

## Архитектура и размещение

| Элемент | Путь |
|---|---|
| Remote service API | `modules/global/src/com/company/hunttech/service/CandidateVacancyMatchAiService.java` |
| DTO прогресса | `modules/global/src/com/company/hunttech/dto/CandidateVacancyMatchProgress.java` |
| Реализация | `modules/core/src/com/company/hunttech/service/CandidateVacancyMatchAiServiceBean.java` |
| AI-функция | `CANDIDATE_VACANCY_MATCH_ANALYZE` через `AiExecutionService.executeText` |
| Web proxy | `hunttech_CandidateVacancyMatchAiService` в `modules/web/src/com/company/hunttech/web-spring.xml` |

Новая AI-функция и миграция не создаются. Анализ использует действующую централизованную конфигурацию AI Control Plane.

## API

```java
CandidateVacancyMatchReport matchVacanciesForCandidate(UUID candidateId);
CandidateVacancyMatchReport matchVacanciesForCandidate(UUID candidateId, UUID operationId);
CandidateVacancyMatchProgress getVacancyMatchProgress(UUID operationId);
CandidateVacancyMatchReport matchCandidatesForVacancy(UUID openPositionId);
```

Старый overload создаёт внутренний `operationId` и сохраняет прежнее поведение callers. Для отображения прогресса экран использует overload с заранее известным идентификатором.

`CandidateVacancyMatchProgress` содержит: `phase`, `statusMessage`, `totalVacancies`, `processedVacancies`, `totalChunks`, `completedChunks`, `failedChunks`, `progressPercent`, `elapsedMillis`, `estimatedRemainingMillis`, `completed`, `success`.

До первого завершённого пакета ETA равен `null`. Затем он рассчитывается по фактическому среднему времени завершённых пакетов. Пока выполняется финальная сборка отчёта, процент ограничен 99; значение 100 устанавливается только при завершённой операции.

## Хранение и ограничения прогресса

Снимки хранятся в потокобезопасной памяти core-узла и удаляются через один час после последнего обновления. Это соответствует текущему синхронному remote-вызову и polling из одного приложения.

В кластерной конфигурации без sticky routing запрос прогресса может попасть на другой core-узел и вернуть `null`. Для такого развертывания состояние следует перенести в распределённое хранилище или таблицу запусков; текущая задача не меняет entity и Liquibase.
