# PdfParserService — разбор PDF и навыков в HRM HuntTech

## Назначение и Бизнес-смысл (What & Why)

`PdfParserService` извлекает текст и изображения из PDF-файлов и определяет навыки, упомянутые в резюме кандидата. Результат используется в карточке `JobCandidateEdit`, чтобы рекрутер видел ключевые компетенции без ручного перечитывания всего резюме.

Критичное требование сервиса — не блокировать открытие карточки кандидата и не переносить в web-слой полный persistence-граф справочника `SkillTree`. Передача тяжёлого графа через сериализацию CUBA может исчерпать Java heap.

## Связи в интерфейсе и Навигация (UI Context & Navigation)

Сервис вызывается из следующих сценариев:

- `JobCandidateEdit` → фоновый анализ последнего резюме после отображения формы;
- фрагмент `Skillsbar` → формирование визуальных меток навыков;
- сервис `ParseCVService` → подсветка компетенций в тексте резюме и вакансии;
- экраны работы с резюме и вакансиями, использующие извлечение текста или изображения из PDF.

Пользователь непосредственно не открывает сервис. Он видит результат на экране кандидата и в связанных HR-сценариях.

## Краткий обзор бизнес-логики поведения (Behavior Summary)

- Анализ пустого текста → сервис возвращает пустой список → экран продолжает открытие без ошибки.
- Загрузка справочника навыков → выполняется скалярный JPQL-запрос → в память не загружаются обратные связи `candidates`, `openPosition`, `candidateCV` и файлы.
- Найдено упоминание навыка → создаётся компактный transient-снимок → в web-слой передаются только ID, название, флаг парсинга, приоритет, комментарий и непосредственный родитель.
- `notParsing = true` → запись пропускается → навык не участвует в анализе.
- Пустое название навыка → запись пропускается → в лог выводится одно агрегированное предупреждение без stack trace для каждой строки.
- Несколько навыков имеют одного родителя → родитель добавляется один раз → объём сериализации не растёт из-за дубликатов.

## API

```java
List<SkillTree> parseSkillTree(String inputText);
```

Публичная сигнатура сохранена для совместимости с существующими вызовами. Возвращаемые `SkillTree` являются transient-снимками, а не загруженными persistence-сущностями.

Снимок содержит только:

- `id`;
- `skillName`;
- `notParsing`;
- `prioritySkill`;
- `comment`;
- непосредственный `skillTree` в виде такого же компактного снимка.

Не заполняются:

- `candidates`;
- `openPosition`;
- `candidateCV`;
- `specialisation`;
- `fileImageLogo`;
- другие обратные и файловые связи.

## Причина и устранение OutOfMemoryError

В старой реализации `DataManager` загружал список сущностей `SkillTree` через view, после чего CUBA сериализовала результат вызова core-сервиса для web-слоя. При открытии `JobCandidateEdit` это приводило к росту `ByteArrayOutputStream` внутри `ObjectOutputStream` и завершалось:

```text
java.lang.OutOfMemoryError: Java heap space
```

Дополнительно записи с `null` в `notParsing` или `skillName` генерировали повторяющиеся `NullPointerException` с полным stack trace.

Текущая реализация:

1. загружает только скалярные значения через `DataManager.loadValues()`;
2. нормализует входной текст один раз;
3. фильтрует некорректные и отключённые записи без исключений;
4. создаёт компактные transient-снимки;
5. дедуплицирует родительские навыки;
6. пишет одно агрегированное предупреждение о некорректных строках.

## Автотесты

Файл:

```text
modules/core/test/com/company/hunttech/core/PdfParserServiceBeanTest.java
```

Проверяются:

- пустой и `null`-текст;
- `null` в названии навыка;
- `notParsing = true`;
- копирование приоритета и комментария;
- отсутствие тяжёлых связей сущности;
- сериализация компактного результата;
- дедупликация общего родителя.

Команда запуска:

```bash
./gradlew :app-core:test --tests "com.company.hunttech.core.PdfParserServiceBeanTest" --no-daemon
```

## Эксплуатационные ограничения

- Анализ навыков должен выполняться после отображения `JobCandidateEdit`, а не синхронно в `onBeforeShow`.
- Полный текст `CandidateCV.textCV` загружается только для последнего резюме и только при запуске фонового анализа.
- Нельзя заменять скалярную проекцию на `_local`, `skillTree-view` или другой широкий view.
- Нельзя возвращать из сервиса коллекции `SkillTree`, непосредственно полученные от `DataManager`.
- Увеличение `-Xmx` является страховкой, но не заменяет ограничение объектного графа.
