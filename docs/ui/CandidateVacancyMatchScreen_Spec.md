# CandidateVacancyMatchScreen — диалог «Подобрать вакансию»

## Business & Context Intro

### Назначение и бизнес-смысл (What & Why)

Диалог помогает рекрутеру подобрать кандидату подходящие открытые вакансии. Перед сопоставлением экран показывает актуализацию навыков кандидата, затем отображает фактический прогресс отбора и AI-анализа. Результат ранжируется по соответствию требований вакансии навыкам и опыту кандидата; решение о дальнейшей работе принимает рекрутер.

### UI Context & Navigation

Экран `hunttech_CandidateVacancyMatch` открывается кнопкой `findSuitableVacancyBtn` с подписью «Подобрать вакансию» из карточки кандидата. Это модальный рабочий диалог: верхняя зона сохраняет контекст кандидата, центральная область содержит таблицу результатов и прокручиваемую панель деталей, кнопка «Закрыть» возвращает пользователя в исходную форму.

### Behavior Summary

- открытие диалога → сравнивается дата последнего изменения резюме с самой поздней датой создания или изменения навыков → AI-актуализация запускается, только если резюме новее либо навыков нет; результат фиксации показывается отдельно от прогресса подбора;
- запуск подбора → выбираются только вакансии `OpenPosition.openClose != true` → экран показывает три этапа, процент выполнения задачи, текущую фазу и ETA;
- завершение AI-пакета → контроллер получает snapshot прогресса → обновляет determinate progress bar без блокировки UI;
- выбор строки результата → справа показываются AI score, подтверждения, пробелы и риски → операционный процент выполнения при этом не меняется;
- действие рекрутера → выполняется существующий controller action → component ID и семантика действий сохранены.

## 2. Связь с моделью данных (Data & Entity Binding)

`matchesDc` хранит `CandidateVacancyMatchItem`; `matchesTable` остаётся связан с контейнером без изменения колонок. Данные прогресса не входят в entity и поступают из remote-safe snapshot сервиса: `operationId`, фаза, текстовый статус, обработанные/всего вакансии, завершённые/всего AI-пакеты, процент и ETA.

Timer facet `analysisProgressTimer` имеет интервал 1000 мс, `autostart=false`, `repeating=true`. Контроллер запускает его только на время активной операции и останавливает после завершения, ошибки или закрытия экрана.

## 4. Модель поведения и интерактивность (Behavior Model)

### 4.1 Прогресс операции

Лента содержит три бизнес-этапа: «Навыки» → «Открытые вакансии» → «AI-сопоставление». Во время обновления навыков полоса показывает активность этапа, процент остаётся 0% до завершения подготовки. После загрузки вакансий прогресс стартует с 15%; далее процент растёт по числу реально обработанных вакансий и завершается на 100% после итоговой сборки отчёта. `analysisPercentLabel` показывает процент выполнения задачи, он не является AI score соответствия. `analysisPhaseLabel` и `statusLabel` объясняют текущую работу, `analysisEtaLabel` показывает прогноз по реальному времени завершённых пакетов. Пока скорость ещё не измерена, экран показывает прошедшее время и сообщает, что оценка ETA рассчитывается.

### 4.2 Статус навыков

`skillRefreshStatusBox` и `skillRefreshStatusLabel` показывают самостоятельный итог проверки: актуальны, обновлены и зафиксированы, пропущены либо ошибка. Актуальность определяется сравнением даты последнего изменения CV с максимальной датой создания/изменения записей навыков. AI запускается только при отсутствии навыков или когда CV новее. Этот статус не используется как процент AI-анализа.

### 4.3 Результаты и детали

Левая панель содержит заголовок, количество совпадений, действия, фильтр решения и таблицу. Правая панель прокручивается независимо и показывает действия по выбранной строке, решение рекрутера, детализацию AI score, совпадающие навыки, пробелы, риски и заключение. `scoresBox` визуально отделён от progress panel.

## 5. Логика управляющих элементов (Actions & Buttons Logic)

Существующие действия и их component ID сохранены: `refreshAnalysisBtn`, `closeBtn`, `takeIntoWorkBtn`, `createInteractionBtn`, `outreachDraftBtn`, `openEntityBtn`, `bulkTakeIntoWorkBtn`, `postponeBtn`, `rejectBtn` и пять `quick*` кнопок. Изменена только группировка: основные действия располагаются в первой строке, решения и открытие карточки — во второй; быстрые действия справа собраны в две компактные колонки.

Новые presentation-компоненты для controller wiring:

| ID | Контракт |
|---|---|
| `analysisProgressTimer` | polling snapshot раз в 1000 мс во время активной операции |
| `skillRefreshStatusLabel` | итог проверки и фиксации навыков кандидата |
| `analysisPhaseLabel` | человекочитаемая текущая фаза |
| `analysisStepsLabel` | позиция в ленте, например «Шаг 2 из 3» |
| `analysisPercentLabel` | процент выполнения задачи: `0%` до завершения проверки навыков, затем растёт по обработанным вакансиям до `100%` |
| `analysisEtaLabel` | оценка оставшегося времени либо «рассчитываем» |
| `analysisProgressBar` | показывает активность обновления навыков и determinate прогресс по AI-пакетам; существующий ID сохранён |
| `statusLabel` | подробный текст текущей операции, существующий ID сохранён |
| `progressStepSkillsLabel` | visual state этапа навыков |
| `progressStepVacanciesLabel` | visual state отбора открытых вакансий |
| `progressStepAiLabel` | visual state AI-сопоставления |

## 6. Визуальная компоновка элементов (Visual Layout Schema)

```text
┌ Контекст кандидата: ФИО · роль · город                         Повторить · Закрыть ┐
├ Навыки кандидата · самостоятельный статус проверки/фиксации                    ┤
├ Текущая фаза                                      Шаг N из 3            NN% ┤
│ progress bar                                                                    │
│ [1 Навыки] [2 Открытые вакансии] [3 AI-сопоставление]             ETA          │
├──────────────────────────────────────┬─────────────────────────────────────────┤
│ Результаты и действия                │ Детали выбранного совпадения (scroll)   │
│ фильтр · таблица                     │ AI score · навыки · пробелы · риски     │
└──────────────────────────────────────┴─────────────────────────────────────────┘
```

Локальный namespace — `candidate-vacancy-match-`. SCSS partial подключён во всех семи темах и содержит только screen-scoped selectors. Карточки используют компактные отступы, элементы допускают сжатие через `min-width: 0`, панель деталей запрещает горизонтальный overflow, длинный текст переносится. При viewport уже 1000 px горизонтальный `SplitPanel` визуально перестраивается в вертикальный стек: результаты над деталями, splitter скрыт, центральная область прокручивается по вертикали. Таблица сохраняет штатную внутреннюю прокрутку CUBA.
