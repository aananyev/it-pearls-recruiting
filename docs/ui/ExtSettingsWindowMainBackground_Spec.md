# ExtSettingsWindowMainBackground — настройка фона главного экрана

> Screen ID: `settings`.  
> Контроллер: `ExtSettingsWindowMainBackground`.  
> Базовая цепочка: `ExtSettingsWindowInterfaceLayout` → `ExtSettingsWindowEmailNavigation` → `ExtSettingsWindow`.

## Назначение и бизнес-смысл (What & Why)

Раздел позволяет пользователю HRM HuntTech выбрать собственный фон либо системный каталог активной темы. Загружаемый файл проходит проверку фактического формата, размеров и декодируемости, автоматически уменьшается, лишается EXIF и сохраняется как ограниченный по размеру JPEG. Это предотвращает загрузку подменённых и чрезмерно больших изображений в рабочий UI.

## UI Context & Navigation

Путь: `SettingsWindow` → вкладка «Интерфейс» → пункт «Фон главного экрана». Пункт переводит фокус к `mainScreenBackgroundUpload`. Вкладки «Обо мне», email, AI и остальные настройки интерфейса не изменяются.

## Behavior Summary

- открытие → читается `UserSettings.fileImageFace` → показывается пользовательский либо системный режим;
- «Выбрать изображение» → открывается штатный file chooser;
- PNG/JPG/JPEG/WEBP выбран → проверяются magic bytes и соответствие расширению;
- заголовок корректен → через `ImageReader` до decode проверяются ширина, высота и число пикселей;
- изображение безопасно → декодируется, уменьшается до `2560 × 1440`, переводится в RGB и кодируется без metadata;
- JPEG больше 4 МБ → снижается quality и при необходимости разрешение;
- нормализация успешна → создаётся маркированный `FileDescriptor`, datasource переводится в пользовательский режим;
- ошибка transport, формата или декодирования → datasource не меняется, временный upload удаляется;
- «Использовать системные фоны» → `fileImageFace` очищается только в редактируемом datasource;
- «ОК» → штатный commit → удаляются только неиспользуемые маркированные файлы → публикуется `MainScreenBackgroundChangedEvent`;
- «Отмена» → «Остаться» → экран остаётся открыт;
- «Отмена» → «Выйти без сохранения» → новые временные нормализованные файлы удаляются, сохранённая настройка не меняется.

## Контракт Upload

`mainScreenBackgroundUpload` не имеет `datasource/property`: связь с `UserSettings.fileImageFace` устанавливается контроллером только после успешной нормализации.

XML-контракт:

- `fileStoragePutMode="IMMEDIATE"`;
- `uploadButtonCaption="Выбрать изображение"`;
- `showFileName="true"`;
- `width="100%"`, `height="36px"`;
- `accept="*.png,*.jpg,*.jpeg,*.webp"`;
- `permittedExtensions=".png,.jpg,.jpeg,.webp"`;
- `fileSizeLimit="15728640"`;
- отдельная бизнес-кнопка очистки.

Статусы:

- `Используется случайный фон активной темы.`;
- `Используется пользовательский фон.`.

## Контракт проверки изображения

| Ограничение | Значение |
|---|---|
| Входной размер | не более 15 МБ |
| Фактические форматы | PNG, JPEG, WEBP |
| Максимальная сторона исходника | 12 000 px |
| Максимум исходных пикселей | 40 000 000 |
| Целевой размер | не более 2560 × 1440 |
| Итоговый формат | JPEG |
| Итоговый размер | не более 4 МБ |
| Metadata/EXIF | не переносится |

WEBP декодируется через pure-Java ImageIO plugin TwelveMonkeys. Итог всегда перекодируется в JPEG, поэтому metadata исходного PNG/JPEG/WEBP не сохраняется.

## Файловая безопасность и Cancel

Временный `IMMEDIATE upload` используется только как вход. После нормализации хранится новый descriptor с префиксом `hrm-main-background-`, а исходный upload удаляется.

`pendingCreated` содержит новые нормализованные файлы текущего несохранённого сеанса формы. При discard они удаляются. После commit активный descriptor сохраняется, остальные новые и заменённые маркированные файлы удаляются. Legacy-фотографии и другие файлы пользователя не удаляются.

## Контракт кнопок

### ОК

Выполняется `super.commit()`. Только после успешного завершения:

1. выполняется cleanup;
2. сбрасывается локальный change flag;
3. публикуется UI-scoped `MainScreenBackgroundChangedEvent`.

### Отмена

Показывается `Остаться в экране или выйти без сохранения?`. Действие «Выйти без сохранения» удаляет `pendingCreated` и вызывает `closeWithDiscard()` без commit и события обновления.

## Проверки Hermes

Обязательны compile, оба профильных теста, `ScreenViewIntegrityTest 8/8`, SCSS, `clean assemble`, clean deploy, HTTP 200 и browser smoke:

- file chooser реально открывается;
- имя файла отображается;
- поддерживаемые форматы проходят;
- spoofed/oversized/corrupt файлы отклоняются;
- пользовательский фон обновляется сразу после «ОК»;
- Cancel не сохраняет фон;
- очистка сразу возвращает системный режим после «ОК»;
- в file storage не остаются неиспользуемые маркированные файлы;
- Tomcat errors NONE.
