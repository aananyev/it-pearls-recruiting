# ExtSettingsWindow — пользовательские настройки HRM HuntTech

## Business & Context Intro

### 1. Назначение и Бизнес-смысл (What & Why)

`ExtSettingsWindow` объединяет персональные настройки текущего пользователя HRM HuntTech в одном стандартном окне: интерфейс, локаль, часовой пояс, профиль, почтовые параметры и подключения к AI API. Размещение API-ключей в `SettingsWindow` исключает отдельную пользовательскую точку навигации и снижает риск того, что персональные секреты будут восприниматься как общесистемная административная настройка.

### 2. Связи в интерфейсе и Навигация (UI Context & Navigation)

Окно открывается через стандартное меню текущего пользователя → **Настройки**. CUBA screen id `settings` переопределён в `modules/web/src/com/company/hunttech/web-screens.xml` и указывает на `ext-settings-window.xml`.

Персональные AI-подключения находятся на вкладке `aiAccessTab`. Отдельный пункт `hunttech_UserAiConfiguration.browse` удалён из главного меню. Администратор по-прежнему может работать с настройками конкретного пользователя через карточку `sec$User.edit`; технический browse/edit-код сущности не удаляется.

### 3. Краткий обзор бизнес-логики поведения (Behavior Summary)

- Открытие SettingsWindow → определяется текущий пользователь сессии → `extUserDs` загружается с `extUser-view` → datasource AI-конфигураций показывает только строки этого пользователя.
- Создание/редактирование подключения → открывается существующий `UserAiConfigurationEdit` → сохраняются провайдер, API-ключ и модель без изменения сервисного контракта.
- Выбор строки → становятся доступны редактирование, удаление и тестирование подключения.
- Нажатие «Тестирование подключения» → вызывается существующий `HrmAiService.testConnection` → пользователю показывается результат.
- Закрытие окна через OK → сохраняются штатные пользовательские и почтовые настройки → AI-конфигурации уже сохранены своими editor-экранами.

## 1. Data Sources и Views

| Элемент | Конфигурация | Назначение |
|---|---|---|
| `extUserDs` | `ExtUser`, view `extUser-view` | Текущий пользователь и его профиль. |
| `userSettingsDs` | `UserSettings`, view `userSettings-view` | Персональные настройки интерфейса и почты. |
| `userAiConfigsDs` | `UserAiConfiguration`, view `userAiConfiguration-view` | Персональные AI API-подключения текущего пользователя. |

Запрос AI datasource:

```jpql
select e from hunttech_UserAiConfiguration e where e.user = :ds$extUserDs
```

Datasource не отображает конфигурации других пользователей.

## 2. Layout и Компоненты

| Компонент | Назначение |
|---|---|
| `settingsTabSheet` | Основной контейнер стандартных пользовательских настроек. |
| `aiAccessTab` | Вкладка персональных AI API-подключений. |
| `aiConfigsTable` | Таблица провайдера, модели и текущего признака. |
| `aiConfigsCreateBtn` | Создание подключения через `UserAiConfigurationEdit`. |
| `aiConfigsEditBtn` | Редактирование выбранного подключения. |
| `aiConfigsRemoveBtn` | Удаление выбранного подключения. |
| `aiConfigsTestBtn` | Реальная проверка выбранного API-подключения. |

API-ключ не выводится в таблицу и редактируется только в модальном editor-экране с секретным полем.

## 3. Lifecycle и Controller

`ExtSettingsWindow.init()`:

1. получает `ExtUser` из `UserSessionSource`;
2. перезагружает пользователя с `extUser-view`;
3. загружает или создаёт `UserSettings`;
4. обновляет datasource AI-конфигураций;
5. настраивает доступность действий таблицы;
6. выполняет стандартную инициализацию `SettingsWindow`.

AI API-логика не переносится в новый сервис или controller: окно переиспользует `UserAiConfigurationEdit` и `HrmAiService`.

## 4. Actions и Бизнес-поведение

| Action | Условие | Результат |
|---|---|---|
| Создать | Всегда доступно | Открывается новая персональная `UserAiConfiguration`. |
| Редактировать | Выбрана строка | Открывается существующая конфигурация. |
| Удалить | Выбрана строка | Запись удаляется через `DataManager`, datasource обновляется. |
| Тестировать | Выбрана строка | `HrmAiService.testConnection` проверяет выбранный ключ и модель. |
| OK | Пользователь завершает настройку | Сохраняются стандартные параметры `UserSettings` и `ExtUser`. |
| Cancel | Пользователь отменяет окно | Выполняется штатное закрытие SettingsWindow. |

## 5. Навигационные ограничения

- Персональные API-ключи открываются только через стандартное окно пользовательских настроек.
- Главный `web-menu.xml` не содержит отдельный пункт `hunttech_UserAiConfiguration.browse`.
- Экран `UserAiConfigurationBrowse` и сервисы не удаляются, чтобы не менять структуру приложения и существующие административные сценарии.
- Административная работа с конкретным пользователем остаётся в `sec$User.edit`.

## 6. Проверки

- `web-screens.xml` содержит override screen id `settings` на `ext-settings-window.xml`.
- `ext-settings-window.xml` содержит `aiAccessTab` и datasource с фильтром по `extUserDs`.
- Главное меню не содержит отдельного `hunttech_UserAiConfiguration.browse`.
- `ExtSettingsWindowAiNavigationContractTest` фиксирует навигационный контракт.
- После изменения требуется `ScreenViewIntegrityTest` 8/8, `BUILD SUCCESSFUL`, локальный deploy и HTTP 200.
