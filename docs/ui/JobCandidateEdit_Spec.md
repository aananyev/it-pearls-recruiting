# JobCandidateEdit — спецификация экрана HRM HuntTech

## Business & Context Intro

### 1. Назначение и Бизнес-смысл (What & Why)

`JobCandidateEdit` — основная рабочая карточка кандидата HRM HuntTech. Экран позволяет рекрутеру вести персональные и профессиональные данные, контакты, историю взаимодействий, резюме, социальные сети, комментарии, историю рассмотрения по вакансиям и список подходящих позиций.

Карточка должна открываться быстро даже для кандидатов с большим числом взаимодействий и объёмными резюме. Оптимизация не должна отключать бизнес-функции или заменять сохраняемые сущности временными объектами.

### 2. Связи в интерфейсе и Навигация (UI Context & Navigation)

Экран открывается:

- из `JobCandidateBrowse` действиями создания и редактирования;
- из экранов подбора кандидатов;
- из карточек резюме и связанных рекрутинговых сценариев;
- из lookup-компонентов, где требуется открыть карточку выбранного кандидата.

Основная навигация выполняется через `tabSheetSocialNetworks`. Доступные вкладки:

- `tabMain` — основные данные;
- `tabPositions` — позиции и вакансии;
- `tabIteraction` — взаимодействия;
- `tabResume` — резюме и файлы;
- `tabContactInfo` — контакты;
- `tabSocialNetworks` — социальные сети;
- `commentsTab` — комментарии;
- `tabHistory` — история.

Из `tabPositions` открывается `IteractionListSimpleBrowse` для выбранной вакансии. Кнопка «HR-Мастер» открывает `OpenPositionMasterBrowse` с текущим кандидатом.

### 3. Краткий обзор бизнес-логики поведения (Behavior Summary)

- Открытие существующего кандидата → загружается основной view → форма отображается без синхронного анализа полного резюме.
- После отображения → фоновая задача читает текст последнего CV → формирует метки навыков.
- Первое открытие `tabPositions` → в фоне агрегируется история взаимодействий → на UI-потоке загружаются история и подходящие вакансии.
- Первое открытие тяжёлой вкладки → соответствующие loaders получают обязательные параметры → данные загружаются один раз.
- Создание нового кандидата → устанавливаются начальные значения → зависимые истории не загружаются до сохранения сущности.
- Сохранение → выполняются штатные валидаторы и `DataContext` → изменения фиксируются в БД.
- Отмена → вызывается `windowClose` → несохранённые изменения отбрасываются по стандартному сценарию CUBA.

## 2. Модель данных, views и loaders

### Основная сущность

`jobCandidateDc` использует view, включающий необходимые связи кандидата. Тяжёлые операции дополнительно изолированы ленивой загрузкой и скалярными запросами.

### Ключевые контейнеры

| Контейнер | Тип данных | Назначение |
|---|---|---|
| `jobCandidateCandidateCvsDc` | `CandidateCV` | Резюме кандидата |
| `jobCandidateIteractionDc` | `IteractionList` | Взаимодействия кандидата |
| `jobCandidateSocialNetworksDc` | `SocialNetworkURLs` | Социальные сети |
| `lastProjectDc` | `KeyValueEntity` | История рассмотрения по вакансиям |
| `suggestOpenPositionDc` | `OpenPosition` | Подходящие вакансии |

### Защищённые loaders

| Loader | Обязательные параметры | Момент запуска |
|---|---|---|
| `lastProjectDl` | `candidate` | Первое открытие `tabPositions` |
| `suggestOpenPositionDl` | `positionType`, опционально `positionTypes` | Первое открытие `tabPositions` |
| loaders взаимодействий | `candidate` | Первое открытие соответствующей вкладки |
| loaders резюме | текущий кандидат | Первое открытие вкладки резюме |

`PreLoadListener` отменяет автоматическую загрузку, пока соответствующий флаг готовности не установлен. Это исключает выполнение JPQL без обязательных параметров.

### View подходящих вакансий

Inline-view `suggestOpenPositionDc` содержит только данные, используемые таблицей и tooltip:

- локальные поля `OpenPosition`;
- `positionType`;
- `projectName`;
- `projectName.projectOwner`;
- `owner`.

Обратные коллекции и несвязанные тяжёлые поля не добавляются.

## 3. Жизненный цикл и бизнес-поведение

### Инициализация

`onInit()`:

1. регистрирует защиту loaders;
2. подключает listener переключения вкладок;
3. сохраняет существующие handlers полей, таблиц и actions;
4. не запускает анализ резюме и историю позиций.

### После отображения

Фоновая загрузка навыков:

1. получает ID кандидата;
2. скалярным запросом загружает `textCV` последнего резюме;
3. вызывает `PdfParserService.parseSkillTree()`;
4. преобразует результат в `SkillLabelData`;
5. на UI-потоке создаёт и отображает `Skillsbar`.

### Вкладка «Позиции и вакансии»

1. `initTabPositions()` проверяет выбранную вкладку и флаги состояния.
2. Для нового кандидата таблицы не выполняют запросы.
3. Для существующего кандидата запускается `BackgroundTask`.
4. В фоне выполняется скалярный JPQL по взаимодействиям.
5. За один проход формируется `Map<UUID, HistoryRowData>`.
6. На UI-потоке устанавливается `candidate` и запускается `lastProjectDl`.
7. Основная и дополнительные позиции передаются в `suggestOpenPositionDl`.
8. При ошибке флаг готовности сбрасывается, разрешая повторную загрузку.

### Сохранение

Сохранение использует штатный `DataContext`. Результаты `PdfParserService` должны состоять из реальных сущностей `SkillTree`, полученных через `DataManager`, поскольку связанные экраны сохраняют их в `CandidateCV.skillTree`.

## 4. Actions, кнопки и обработчики

| Компонент/действие | Условие | Результат |
|---|---|---|
| `windowCommitAndClose` | форма валидна | сохраняет кандидата и закрывает экран |
| `windowClose` | пользователь отменяет | закрывает экран без сохранения |
| `lastProjectTable` → «Просмотр» | выбрана строка вакансии | открывает взаимодействия кандидата по вакансии |
| `suggestVacancyTable` | первая загрузка вкладки | показывает открытые вакансии по основной/дополнительным позициям |
| `jobCandidateIteractionListTable.create/edit/remove` | разрешена работа с кандидатом | изменяет взаимодействия |
| `jobCandidateCandidateCvTable.create/edit/remove` | открыт раздел резюме | изменяет резюме и файлы |
| `fileImageFaceUpload` | выбран файл | обновляет фотографию кандидата |
| `openPositionMasterBrowseButton` | текущий кандидат доступен | открывает HR-Мастер |
| `blockCandidateButton` | подтверждено действие | блокирует или разрешает взаимодействия |

Существующие component ID, actions, invoke и генераторы колонок не переименовываются.

## 5. Визуальная компоновка

### Основная структура

```text
jobCandidateMainLayout
├── jobCandidateSidebar
│   ├── профиль и фотография
│   ├── статус и рейтинг
│   ├── контакты
│   └── HR-Мастер
└── jobCandidateWorkspace
    ├── верхняя панель действий
    ├── tabSheetSocialNetworks
    │   ├── Основное
    │   ├── Позиции и вакансии
    │   ├── Взаимодействия
    │   ├── Резюме и файлы
    │   ├── Контакты
    │   ├── Социальные сети
    │   ├── Комментарии
    │   └── История
    └── нижняя визуальная панель сохранения
```

### Правила темы

- Все SCSS-селекторы ограничены `.job-candidate-editor`.
- Левая панель имеет фиксированную ширину 286 px, адаптивно 258 px.
- Рабочая область занимает оставшуюся ширину.
- Основные карточки используют равные flex-доли.
- `expand` каждого CUBA-контейнера указывает только на непосредственного дочернего компонента.
- Глобальные `.v-table`, `.v-label` и `.v-button` не изменяются.

## 6. Производительность, ошибки и контроль качества

### Исключённые ошибки

- `There is no component with id ... to expand`;
- `Unable to find an instance ... dictionatysTavlesHBox`;
- `Table doesn't have data binding` для `lastProjectTable`;
- `OutOfMemoryError: Java heap space` при сериализации всего справочника навыков;
- серия `NullPointerException` для некорректных `SkillTree`;
- `unfetched attribute` в tooltip подходящей вакансии;
- выполнение loader истории без параметра `candidate`.

### Обязательные проверки

```bash
./gradlew :app-core:test \
  --tests "com.company.hunttech.core.PdfParserServiceBeanTest" \
  --no-daemon \
  --stacktrace

./gradlew test \
  --tests '*ScreenViewIntegrityTest*' \
  --no-daemon \
  --stacktrace

./gradlew :app-web:buildScssThemes --no-daemon --stacktrace
./gradlew clean deploy -x test --no-daemon --stacktrace
```

Функционально проверить:

- пять открытий кандидата с большим CV;
- все вкладки;
- историю и подходящие вакансии;
- tooltip вакансии с заполненными и пустыми связанными полями;
- переход к взаимодействиям;
- пересканирование и сохранение `CandidateCV.skillTree`;
- сохранение и отмену карточки;
- фотографию;
- отсутствие новых OOM и dependency injection ошибок в `catalina.out`.
