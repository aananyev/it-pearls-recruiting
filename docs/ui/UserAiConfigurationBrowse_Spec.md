# UserAiConfigurationBrowse — выбор текущей нейросети

## Business & Context Intro

### 1. Назначение и Бизнес-смысл (What & Why)

Экран хранит несколько настроенных AI API-конфигураций пользователей и позволяет администратору выбрать ровно одну нейросеть, которая отвечает на системные кнопки AI-анализа в `OpenPositionEdit`, `CandidateCVEdit`, `IteractionListEdit` и других экранах HRM HuntTech.

### 2. Связи в интерфейсе и Навигация (UI Context & Navigation)

Экран открывается из административных настроек AI. `UserAiConfigurationEdit` используется для провайдера, API-ключа и модели; текущая нейросеть выбирается кнопкой «Использовать для AI-анализа» непосредственно в browse-экране.

### 3. Краткий обзор бизнес-логики поведения (Behavior Summary)

- Выбор нетекущей строки → кнопка выбора активируется → администратор может назначить провайдера текущим.
- Нажатие «Использовать для AI-анализа» → core-сервис в одной транзакции снимает текущий признак у остальных конфигураций владельца → выбранная строка получает `isActive=true`.
- Нажатие «Тест AI» → выбранная запись перезагружается с секретным API-ключом → тестируется конкретная конфигурация независимо от текущего выбора.
- Нажатие AI-анализа на бизнес-экране → сервис ищет единственную текущую конфигурацию пользователя → запрос направляется выбранному провайдеру.

## 1. Data Container и View

| Элемент | Конфигурация | Назначение |
|---|---|---|
| `userAiConfigurationsDc` | `CollectionContainer<UserAiConfiguration>` | Список сохранённых подключений. |
| View | `userAiConfiguration-browse-view` | Не содержит `apiKey`, но содержит пользователя, провайдера, модель и текущий признак. |
| Таблица | `userAiConfigurationsTable` | Выбор строки, CRUD, тест и назначение текущей конфигурации. |

## 2. Loader и Query

```jpql
select e from hunttech_UserAiConfiguration e order by e.user.login, e.providerCode
```

Loader отображает конфигурации в стабильном порядке по пользователю и провайдеру. Секретный API-ключ не загружается в browse-view.

## 3. Lifecycle и Controller

`onInit` блокирует `testBtn` и `makeCurrentBtn`, пока строка не выбрана. Selection listener обновляет доступность действий. После переключения текущего провайдера loader перезагружается, чтобы таблица сразу показывала фактическое состояние БД.

## 4. Actions и Бизнес-поведение

| Action | Результат |
|---|---|
| `create/edit/remove` | Стандартное управление конфигурациями. |
| `onMakeCurrentBtnClick` | Вызывает `HrmAiService.setCurrentConfiguration(UUID)`. |
| `onTestBtnClick` | Перезагружает edit-view и вызывает `HrmAiService.testConnection`. |

Ошибки core-сервиса выводятся локализованным error notification.

## 5. Layout и Локализация

Таблица использует локализованные captions пользователя, провайдера, текущего признака и модели. Кнопки выбора и тестирования также берут captions/descriptions из `messages.properties` либо `messages_ru.properties`.

## 6. Инварианты и Проверки

- Для одного пользователя не более одной неудалённой строки `isActive=true`.
- Ограничение обеспечивается core-транзакцией и частичным уникальным индексом PostgreSQL.
- Остальные конфигурации сохраняются и доступны для тестирования/явного providerCode.
- После переключения SQL-проверка возвращает `count(*) <= 1` по каждому `USER_ID`.
- `ScreenViewIntegrityTest` проходит 8/8.
