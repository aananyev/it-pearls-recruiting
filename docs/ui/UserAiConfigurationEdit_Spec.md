# UserAiConfigurationEdit — редактор доступа к AI API

## Business & Context Intro

### 1. Назначение и Бизнес-смысл (What & Why)

Экран позволяет сохранить подключение пользователя к AI-провайдеру: код провайдера, API-ключ и модель. Редактор не переключает рабочую нейросеть автоматически, чтобы добавление резервного подключения не изменяло поведение системных кнопок AI-анализа.

### 2. Связи в интерфейсе и Навигация (UI Context & Navigation)

Открывается из `UserAiConfigurationBrowse` и из связанных пользовательских настроек. После сохранения строка остаётся резервной, пока администратор не назначит её текущей в browse-экране.

### 3. Краткий обзор бизнес-логики поведения (Behavior Summary)

- Создание → владелец подставляется из parent context при его наличии → `isActive=false`.
- Выбор провайдера → при пустой или автоматически заполненной модели подставляется рекомендуемое имя модели.
- Ручное изменение модели → последующее переключение провайдера не затирает введённое значение безусловно.
- Сохранение → обязательные provider/API key проходят validation → запись сохраняется как текущая или резервная в соответствии с существующим признаком.

## 1. Data Container и View

| Элемент | Конфигурация | Назначение |
|---|---|---|
| `userAiConfigurationDc` | `InstanceContainer<UserAiConfiguration>` | Редактируемая API-конфигурация. |
| View | `userAiConfiguration-edit-view` | Включает локальные поля и владельца. |

## 2. Поля и Bindings

| Component | Property | Поведение |
|---|---|---|
| `providerCodeField` | `providerCode` | Lookup поддерживаемых провайдеров, обязателен. |
| `apiKeyField` | `apiKey` | PasswordField, обязателен. |
| `defaultModelNameField` | `defaultModelName` | Рекомендуемая модель с возможностью ручного изменения. |
| `isActiveField` | `isActive` | Только чтение; выбор выполняется в browse. |

## 3. Lifecycle и Controller

- `onInit` формирует карту провайдеров и подписывает listener модели.
- `onInitEntity` назначает parent user и устанавливает `isActive=false`.
- `onBeforeShow` повторно гарантирует owner для новой entity и синхронизирует рекомендуемую модель.

## 4. Actions

`windowCommitAndClose` сохраняет запись, `windowClose` отменяет изменения. Переключение текущей нейросети в editor отсутствует намеренно и выполняется только атомарным core-действием browse-экрана.

## 5. Layout и Локализация

- Диалог 650×560 px.
- Captions размещены сверху.
- Форма находится в `contentScrollBox`.
- Панель OK/Cancel находится вне прокрутки.
- Русские и английские captions берутся из screen message packs.

## 6. Проверки и Критерии приёмки

- Все подписи читаются в RU/EN локалях.
- OK и Cancel постоянно видимы.
- API key отображается как секретное поле и отсутствует в browse-view.
- Новая строка создаётся с `isActive=false`.
- Ручное имя модели не затирается неожиданно.
- `ScreenViewIntegrityTest` проходит 8/8.
