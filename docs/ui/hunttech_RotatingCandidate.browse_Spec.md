# `hunttech_RotatingCandidate.browse` — Кандидаты в работе

## Business & Context Intro

### Назначение и бизнес-смысл (What & Why)

Экран показывает рабочие записи `IteractionList` по кандидатам и вакансиям, чтобы рекрутер мог видеть текущие кейсы и переходить к карточке кандидата, резюме и предложениям вакансий. При открытии список ограничен последними 30 днями и текущим пользователем. Это позволяет видеть актуальную работу и не оставлять таблицу пустой, когда взаимодействий не было за последнюю неделю.

### UI Context & Navigation

- Меню: «HR-мастер → Кандидаты в работе»; экран контролируется `hunttech_RotatingCandidate.browse`.
- Этот экран — legacy рабочая таблица с фильтрами и деталями выбранного кандидата.
- Новый Dashboard Add-on открывается отдельно: «Подбор → Дашборды рекрутера → Kanban». У него собственный экран и набор колонок; название короткое — «Kanban».

### Behavior Summary

- Открытие экрана → выбран период «За месяц» → загрузчик применяет интервал 30 дней и показывает подходящие записи.
- Открытие экрана → выбрано «Только мои» → список ограничен login текущего пользователя.
- Выбор другого периода → меняется параметр `daysBetween` либо снимается ограничение периода → таблица перезагружается.
- Выбор рекрутера или фильтра кейса/должности/статуса → соответствующие параметры и данные обновляются.
- Отсутствие записей в выбранном периоде → таблица остаётся пустой; пользователь может расширить период до «За все время».

## Invocation & Context

Контроллер: `com.company.hunttech.web.screens.rotatingcandidates.RotatingCandidateBrowse`.

`@LoadDataBeforeShow` и `onBeforeShow` подготавливают список пользователей, задают стартовые фильтры и загружают таблицу. Для рекрутеров и исследователей список выбора пользователей ограничен активными учетными записями.

## Data & Entity Binding

- `iteractionListsDc` содержит read-only записи `hunttech_IteractionList`; `iteractionListsDl` сортирует их по ФИО кандидата.
- View включает кандидата и используемые таблицей связанные сведения: город, резюме, должность, фото, вакансию, рекрутера и тип взаимодействия.
- Запрос поддерживает фильтры по `createdBy`, признаку завершения кейса, дате взаимодействия, ФИО и должности.
- `userDc` заполняет `recruterLookupPickerField`; список пользователей сортируется по имени.
- Контейнеры резюме, последних вакансий, взаимодействий и открытых вакансий обслуживают детали выбранного кандидата и блок предложений.

## Form Hierarchy

Экран состоит из панели фильтров периода, рекрутера и состояния кейса, основной таблицы взаимодействий и блоков детализации выбранного кандидата. Таблица остается основным списком; карточка кандидата и предложение вакансий используют выбранную строку.

## Behavior Model

### Стартовые фильтры

- Период: значение `3`, подпись «За месяц», параметр `daysBetween = 30`.
- Рекрутер: значение `1`, подпись «Только мои», параметр `recrutier` равен login текущего пользователя.
- Состояние кейса: значение `0` («Все»).

### Изменение периода

| Выбор | Значение | Условие загрузки |
|---|---:|---|
| За все время | 0 | параметр `daysBetween` удаляется |
| За 3 дня | 1 | `daysBetween = 3` |
| За 7 дней | 2 | `daysBetween = 7` |
| За месяц | 3 | `daysBetween = 30` |

Каждое изменение периода вызывает `iteractionListsDl.load()`. Параметры фильтрации не меняют состав view или бизнес-смысл записей.

## Actions & Buttons Logic

Группы выбора периода, рекрутера и состояния кейса обновляют параметры loader. Lookup рекрутера, взаимодействия и должности включаются для соответствующего режима. Детальные действия таблицы и карточки остаются штатными и не менялись в этой задаче.

## Visual Layout Schema

Компоновка и стили таблицы, панели фильтров, карточки кандидата и предложений вакансий не менялись. Изменено только стартовое значение существующей группы «Период».
